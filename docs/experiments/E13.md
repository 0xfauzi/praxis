# E13: can each language's toolchain serve as the outside judge for praxis's import edges?

## Why this matters (30 seconds)

Praxis scores structural items against the import graph that X1 extracts (design 03
section 3.1). X1 reads Python only. Before praxis adds extractors for TypeScript and
JavaScript, Go, Rust and Java, it needs a way to know whether an extractor is right
that does not depend on praxis grading its own work. Every language's toolchain already
knows its module graph. `experiments/E13/oracle.py` asks each toolchain for that graph
and returns it in one shape, so that any praxis extractor can be compared with it edge
for edge. The comparison code is proven on Python, where X1 and an oracle both exist.

## Decision rule, written before the run (2026-10-19)

This rule is quoted from the module docstring of `experiments/E13/oracle.py`. It was
written before the first run.

**Python (gated).** For each of praxis, telltale and systemap at its committed HEAD,
read from a fresh `git clone` under the scratch directory with its own
`uv sync --frozen` (deleted at exit), the oracle is the set of distinct (importer file,
imported file) pairs that the tracer records while the repository's own test suite runs
(`uv run --frozen pytest -q -p no:cacheprovider`, every test, pass or fail). If the
suite writes no trace, a module import sweep replaces it. X1 is
`praxis.extract.static_imports(clone, lambda p: p)` over the same clone. Both sides keep
only git-listed `.py` files and drop self-pairs.

- PASS iff, on each of the three repositories, X1's recall of the oracle's file-level
  edges is at least 0.95. Recall counts every oracle edge, including the edges made by
  `importlib.import_module` or an explicit `__import__(...)` call. An empty oracle is a
  FAIL, because its recall is undefined. Precision and directory-level figures are
  reported and not gated.

**Other languages (gated on the harness only).** TypeScript and JavaScript, Go, Rust and
Java, each on at least two public repositories cloned over HTTPS:

- PASS iff each adapter returns a non-empty edge list with zero adapter errors on each
  of its repositories, with edge counts and wall time recorded. An adapter error is an
  exception in the adapter, or a toolchain run that leaves nothing to parse.
  Diagnostics that the toolchain reports about the repository are counted and are not
  adapter errors, if an edge list came out.

**TypeScript route.** On pmndrs/zustand, run both the `tsc --traceResolution` parse and
the compiler-API script. Keep the route whose edge set contains the other's. If the two
sets are equal, keep the compiler API.

**Prediction.** Python recall 0.97 to 1.0 on all three repositories, the misses being
importlib calls and imports through a path a test put on sys.path. Precision 0.5 to 0.8.

## What we did

One stand-alone runner, standard library only: `experiments/E13/oracle.py`, with its
shared shapes in `shapes.py` and one adapter module per language beside it
(`py_tracer.py`, `ts.py`, `go_lang.py`, `rust.py`, `java.py`). Run with
`uv run python experiments/E13/oracle.py LANG REPO... --json OUT --scratch DIR`.
`--selfcheck` runs the planted case described below. Every adapter returns an `Oracle`:
`edges`, a sorted list of distinct (src, dst) repository-relative POSIX paths at file
level, `dir_edges`, the same at directory level with pairs inside one directory
dropped, `unresolved`, a count of in-repository references the toolchain could not
resolve to a file, `seconds`, and a `detail` dictionary of counts. External packages
are dropped. `compare(oracle_edges, praxis_edges)` returns oracle, praxis and shared
counts, recall, precision and the `missing` and `extra` lists. It refuses an edge list
that names a pair twice. A ratio over an empty side is `None`, not 0 or 1.
`compare_levels` does the same at file level and, through `to_dirs`, at directory level.

The adapters, and the toolchain output each one parses:

- **Python: runtime import tracing.** The tracer wraps `builtins.__import__` and
  `importlib.import_module`. A `sys.meta_path` finder was rejected because it is asked
  only when a module is first loaded. A later importer gets the module from
  `sys.modules` and the finder never sees that importer. `sys.setprofile` was rejected
  because CPython runs an `import` statement through the `IMPORT_NAME` opcode with no
  Python-level call event. When `builtins.__import__` is replaced, `IMPORT_NAME` calls
  the replacement for every executed import statement, cached or not, and passes the
  importer's globals. The importer is `globals["__file__"]`. A relative import is
  resolved with `importlib.util.resolve_name` against `__package__`. The target is the
  module that the statement names. For `import a.b.c` the target is `a.b.c`. For
  `from a import b` the target is `a.b` if that is a module, and `a` if `b` is an
  attribute. X1 resolves the same way: the deepest indexed name wins. An `__import__`
  call without globals is attributed to the caller's frame and tagged `call`.
  `import_module` calls are tagged `import_module`, and import statements are tagged
  `statement`. A target inside the repository that has no `__file__` (a namespace
  package) is counted as unresolved. Each process writes its distinct
  (importer, imported, kind) triples to a JSON file at exit. Two install routes exist.
  Run 1 used `pythonpath`: a `sitecustomize.py` reached through `PYTHONPATH`, with its
  output directory in environment variables. Run 2 used `pth`: a module and a `.pth`
  file written into the clone's own `.venv` site-packages, with the paths written into
  the module. The `pth` route reaches processes that the suite starts with a scrubbed
  environment, and the `pythonpath` route does not. Run 2 was added after run 1 showed
  that praxis's CLI tests start `praxis` with a named environment
  (`tests/integration/test_cli.py`, `_praxis`), so the `pythonpath` route traced only 5
  processes there.
- **TypeScript and JavaScript.** The project's `tsconfig.json`. A plain JavaScript
  repository gets a generated config, written outside the repository, with `allowJs`
  true, `checkJs` false, `module` and `moduleResolution` set to `nodenext`,
  `maxNodeModuleJsDepth` 0, `types` empty and absolute `include` globs for `.js`,
  `.cjs`, `.mjs` and `.jsx`. Route `api` is a node script run with the global
  `typescript.js` 6.0.2. The script calls `ts.getParsedCommandLineOfConfigFile`, then
  `ts.createProgram`, then `program.forEachResolvedModule`. For each resolution it
  reads the containing file (`program.getSourceFileByPath(filePath).fileName`) and
  `resolvedModule.resolvedFileName`. An unresolved resolution gives the specifier.
  Route `trace` runs `tsc --noEmit --traceResolution -p CONFIG` and parses three line
  forms: `======== Resolving module 'S' from 'FILE'. ========`,
  `======== Module name 'S' was successfully resolved to 'FILE'[ with Package ID ...]. ========`
  and `======== Module name 'S' was not resolved. ========`. A resolved file under
  `node_modules` or outside the repository is dropped. An unresolved relative specifier
  (starting with `.` or `/`) counts as unresolved. An unresolved bare specifier is an
  external package, because no `npm install` was run, and is counted separately.
- **Go.** `go list -e -deps -json ./...` with `GOTOOLCHAIN=local`, `GOWORK=off`,
  `GOFLAGS=-mod=readonly`, and `GOPATH`, `GOMODCACHE` and `GOCACHE` in the scratch
  directory. The output is a stream of concatenated objects, parsed with
  `json.JSONDecoder.raw_decode`. The fields read are `ImportPath`, `Dir`,
  `Module.Main`, `Imports`, `TestImports`, `XTestImports`, `GoFiles`, `CgoFiles`,
  `TestGoFiles`, `XTestGoFiles` and `Error`. The directory level is each main-module
  package's imports that are main-module packages. `go list` gives no per-file
  imports (it has no `ImportPos` field; searched in the `-json` output), so the file
  level uses a 30-line Go program, embedded in the runner and run with `go run`
  outside the repository. That program parses each file with `go/parser` in
  `ImportsOnly` mode and prints its import paths. A file-level edge is
  (file, imported package directory). Go's unit is the package, and praxis's component
  rules treat a directory as a component, so the directory level is the one that
  matters. Both levels are produced. An import under the module path that names no
  listed package counts as unresolved.
- **Rust.** `cargo metadata --no-deps --offline --format-version 1` gives the workspace
  packages: `name`, `manifest_path`, `edition`, `features`, `targets` (`kind`,
  `src_path`) and `dependencies` (`name`, `rename`, `path`, `kind`). A crate-level edge
  is crate root to dependency crate root for each path dependency inside the
  workspace (lib target first, else bin). The directory level is the same between
  manifest directories. File membership comes from rustc dep-info. For every target
  except build scripts, the runner runs `rustc --emit=dep-info` twice, once plain and
  once with `--test`. Each run passes the package's edition and default features
  (expanded within the crate) and `--extern` for every declared dependency. Each
  extern points to an empty stub rlib, which is compiled from an empty file. The first
  rule's prerequisites in the `.d` file are the source files the crate loads. No
  dependency is built and no build script or proc macro is run. Without the stubs,
  rustc stopped at `extern crate` (E0463) and wrote no dep-info for `grep` (ripgrep)
  and `regex-test` (regex). That was the first run's two adapter errors, before the
  stubs existed.
- **Java.** Source roots are `src/main/java` directories. The runner runs
  `javac -d TMP -proc:none -nowarn -encoding UTF-8 -implicit:none @sources`, then
  `jdeps -verbose:class -filter:none TMP`. Without `-filter:none`, jdeps by default
  drops dependencies within one package. The line form parsed is
  `   pkg.A   -> pkg.B   classes`. A class is mapped to its source file by the
  `SourceFile` attribute, which the runner reads from the class file with a
  class-file parser of about 50 lines, joined to the package path under each source
  root. That handles nested classes (`A$B`) and non-public top-level classes declared
  in another file. A class whose source cannot be found counts as unresolved.

**Self-check.** A planted two-file repository: `a.py` holds `from pkg import b`, and
`pkg/b.py` imports `a` only under `if TYPE_CHECKING:`. Worked by hand, running
`a.py` executes one import, so the oracle is {(a.py, pkg/b.py)}. X1 resolves both
statements, so X1 holds that edge and (pkg/b.py, a.py). The file level is recall 1/1,
precision 1/2, extra [(pkg/b.py, a.py)]. The directory level is recall 1, precision
1/2, extra [(pkg, .)]. Both tracer routes must give exactly that. The `pth` route runs
in a `python -m venv --without-pip` venv. Pure assertions cover a ratio over an empty
side (`None`) and `to_dirs` dropping a same-directory pair. The self-check passes. Four
deliberate breaks each made it fail: the tracer targets the package instead of the
submodule, recall divides by the praxis side, `to_dirs` keeps same-directory pairs, and
the `.pth` file is not written.

**Cross-checks of the oracles themselves.** For TypeScript, both routes ran on all four
repositories. For Rust, `cargo check --lib --message-format=json` ran on rust-lang/regex
for `regex`, `regex-lite`, `regex-syntax` and `regex-automata`, after `cargo metadata`
(full) showed no build script or proc macro in their normal-dependency closure
(aho-corasick, memchr, log). The `.d` files cargo wrote were compared with the stub
route. For Java, the jdeps edges were compared with in-repository `import` statements
read by a regex, as an independent approximation. For Go, the file level lifted to
directories was compared with the `go list` directory level.

## Verdict

- **Python: PASS.** Recall 1.000, 0.995 and 0.998, all at least 0.95, in both tracer
  runs. The prediction held for recall. For precision it held on praxis and telltale
  (0.77 each) and missed on systemap (0.92, above the predicted 0.5 to 0.8).
- **TypeScript and JavaScript: PASS.** Four repositories, zero adapter errors, no empty
  list.
- **TypeScript route: compiler API kept.** The two routes gave equal edge sets on
  zustand, so the rule picks the API. They were also equal on the other three
  repositories.
- **Go: FAIL as written.** Three of four repositories passed. gin was one of the
  adapter's repositories and gave an adapter error under `GOTOOLCHAIN=local`, because
  the installed go1.24.7 is older than gin's go.mod requires. The rule asks for zero
  adapter errors on each repository, so the clause fails as written. With
  `E13_GOTOOLCHAIN=auto` the toolchain fetched go1.26.0 and the adapter produced
  edges. That rerun came after the failure and does not change the verdict.
- **Rust: PASS** on ripgrep and regex, with the stub externs. The first version, without
  stubs, gave 2 adapter errors. It was fixed before any edge list was recorded, and the
  fix was then checked against `cargo check`.
- **Java: PASS.** Three repositories, zero adapter errors.

## What it means

- The comparison code works. On real repositories it reproduces the known blind spots
  exactly: every X1 miss is an `importlib` call that X1 already counts as a blind spot.
  At file level, X1 finds every import that the three suites execute through an import
  statement.
- Precision is a measure of what the tests run, not of X1. Over X1 edges whose source
  file ran, precision is 0.98 (praxis), 0.88 (telltale) and 0.995 (systemap). The rest
  is TYPE_CHECKING imports (praxis 2, telltale 73, systemap 10) and 3 function-level
  imports that no test called. A static extractor for another language should be gated
  on recall against a static oracle, not against a runtime one.
- For TypeScript and JavaScript, Go, Rust and Java, the toolchain oracles are static and
  complete for what they read. A future praxis extractor for those languages can be
  gated on recall and precision together. Rust is the exception, because the stable
  toolchain gives only crate-level edges (see below).
- The Go adapter depends on the installed toolchain being at least as new as each
  repository's `go` line. This is a property of the owner's machine, and the adapter
  reports it as a toolchain refusal, not as an empty graph.

## What each oracle cannot see

- **Python (runtime).** It sees only what executes: an import on a path no test reaches,
  any import under `if TYPE_CHECKING:`, and every file the suite never imports. It does
  not see a process started with `-S` (no site, so no `.pth`), a process ended by
  `os._exit`, a process started by an interpreter outside the clone's venv, or (with
  the `pythonpath` route) a process with a scrubbed environment. It sees
  `__import__(name, globals())` with explicit globals as a statement. A target that is
  a namespace package has no file and counts as unresolved (0 here). Edges whose ends
  are not git-listed (the clone's `.venv`) are dropped: 555 on praxis, 610 on telltale
  and 1135 on systemap in run 2.
- **TypeScript and JavaScript.** Only files in the config's program: zustand's
  `examples/` and immer's `__tests__`, `website` and perf files are outside the root
  config (31 of 51 and 17 of 55 files covered). Specifiers that are not literals
  (`require(variable)`) and anything a bundler resolves by its own config are not seen.
  Without `npm install`, a workspace package imported by its bare name would count as
  external (in these four repositories such self-imports appear only in comments). A `paths` alias that resolves
  inside the repository is seen (zustand's `zustand` alias to `./src/index.ts`).
- **Go.** Files excluded by build constraints for this GOOS and GOARCH (`IgnoredGoFiles`
  are not read), `testdata` directories, nested modules (only the main module is read),
  and repositories whose `go` line is newer than the toolchain under
  `GOTOOLCHAIN=local`. The file level is file to package directory, never file to
  file. Go has no finer unit.
- **Rust.** The stable toolchain gives crate-to-crate edges (cargo metadata) and the set
  of files each crate compiles (dep-info). It does not give module-to-module `use`
  edges, and the `.d` file does not say which file declared which `mod`. Those need
  nightly (`-Zunpretty`), or rust-analyzer, which is not installed here (the rustup
  shim is present without the component). So the finest honest level is crate edges
  plus crate membership. A `mod` declared inside a macro from a dependency (such as
  `cfg_if!`) would be missed by the stub route. Features other than the default set are
  not enabled.
- **Java.** Compile-time references only. A `static final` constant that javac inlines
  is not seen, nor are references used only in Javadoc (4 on commons-lang),
  annotations with source retention, reflection, and test sources (they need JUnit on
  the classpath). Only `src/main/java` roots are read. Classes must compile, so a
  repository whose main sources need dependencies would give a partial list with javac
  errors counted.

## What we rejected

- A `sys.meta_path` finder for the Python oracle (it misses every importer after the
  first) and `sys.setprofile` (it gets no event for an import statement).
- Gating Python precision. The runtime oracle cannot see unexecuted code, so a low
  precision would blame X1 for the test suite's coverage.
- Running `cargo check` as the Rust oracle. It builds dependencies and runs their build
  scripts and proc macros, which is code from the network. It was used once as a
  judge, on a closure verified to have neither, and agreed with the stub route on all
  124 files.
- Parsing Go import blocks in Python. The toolchain's own `go/parser` is the oracle.
- jdeps with its default filter. It drops same-package dependencies, which are most of a
  Java package's edges.

## How sure we are

- The non-Python oracles are deterministic toolchain output at named commits. Each was
  checked against a second route: TypeScript trace against API, Rust stub against
  cargo, Go file against directory, and Java jdeps against import statements.
- The Python oracle depends on the suite, and its numbers hold for these suites at these
  commits. Recall was identical across two runs with different tracer routes on
  telltale and systemap. On praxis it rose from 76 to 106 oracle edges with no new
  miss.
- The Python recall figures count every oracle edge. The 7 importlib misses are the
  whole gap to 1.0.
- Wall times are from one container under parallel load, and the Go cold time includes
  compiling the helper. All of them need measuring on the owner's machine before any
  hook budget relies on them.

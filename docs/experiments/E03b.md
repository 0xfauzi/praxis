# E03b: does diffing against the session's base commit stop an agent's commit from erasing its own work?

## Why this matters (30 seconds)

The recorder first diffed the working tree against HEAD. When the agent ran `git commit`,
its lines left the diff, so the commit call read as the agent deleting everything it had
written. F1's `o_first`, S2's divergences and S4's removals all read those deltas. Design
03 section 5.1 moves the diff to the commit HEAD was at when the session started, and
this run checks the fix before any outcome row depends on it.

## Decision rule, written before the run (2026-10-19)

Four scenarios, each in a fresh repository holding `pkg/calc.py` in one commit, driven
through `praxis hook` one process per event with the Claude Code 2.1.303 payloads in
`fixtures/claude/2.1.303` (session id, cwd and tool_use_id replaced):

| Scenario | What happens | The installed binary passes iff |
|---|---|---|
| commit | Edit calc.py, Write extra.py, then a Bash call that runs `git add -A && git commit` | the commit call writes 0 agent_deltas rows; the session has exactly three +1 rows; at Stop calc.py has agent 2 and extra.py agent 1, human 0, coverage full |
| sed | one Bash call runs `sed -i` on calc.py and `git commit -qam` | that call writes two +1 rows on calc.py; at Stop calc.py has agent 2 |
| pull | Edit calc.py, then the owner commits a new file between tool calls | every Stop attribution row is `partial` with `head_moved_outside_tool`; calc.py still has agent 2 |
| checkout | the owner checks out the parent of the base commit | the Stop hook_events row is `unobservable` with `head_not_descendant` |

The same scenarios were also run against the recorder at commit e9b5e3a (HEAD diffing),
from a scratch clone, as the before condition. Predicted before the run: the before
recorder's commit call writes three -1 rows and its Stop attributes nothing to the
agent. Its sed call writes no row at all.

## What we did

`experiments/E03b/base_sha.py`. The after condition is the installed `praxis` binary,
an editable install of the working tree with B1's recorder changes. The before condition
is `python -c "from praxis.cli import main"` with `PYTHONPATH` set to a scratch clone at
e9b5e3a. Each condition has its own `$PRAXIS_HOME` and `HOME` under one temporary
directory, deleted at exit. The verdict function is applied to both conditions.

## What we measured

| Scenario | Before (HEAD diffing) | After (base-sha diffing) |
|---|---|---|
| commit: rows from the commit call | three -1 rows (calc.py twice, extra.py) | none |
| commit: Stop attribution | no row; "0 files attributed" | calc.py agent 2, extra.py agent 1, human 0, full |
| sed: rows from the one Bash call | none | two +1 rows on calc.py |
| sed: Stop attribution | no row; the edit is lost | calc.py agent 2, full |
| pull: Stop attribution | calc.py agent 2, `full`; owner.txt absent | calc.py agent 2 and owner.txt human 1, both `partial`, `head_moved_outside_tool` |
| checkout: Stop event | `ok`, "0 files attributed" | `unobservable`, `head_not_descendant` |

Verdict on the after condition: commit, sed, pull and checkout all true. **Rule: PASS.**
Verdict on the before condition: all four false, as predicted.

## What it means

- An agent's commit now moves no line. A `sed && git commit` in one Bash call keeps its
  edit instead of losing it. Excluding commit calls would have lost that edit too
  (design 5.1), so base-sha diffing is the only one of the three rules that records it.
- The old recorder hid two failures as successes. A checkout to an older commit read as a
  clean session ("0 files attributed", outcome `ok`). An owner commit between tool calls
  removed the owner's own lines from view with coverage `full`. The new recorder labels
  the first `unobservable` and the second `partial`.
- Recorder assumption 3 ("lines are compared relative to HEAD") is replaced by the base
  commit assumption on every attribution row.

## What we rejected

- Excluding Bash calls that contain `git commit`. The sed scenario shows such a call can
  carry the only edit in the segment.
- Re-basing to the new HEAD after an owner pull. A pull brings in other people's lines,
  which would then count as nobody's. The warning plus `partial` keeps them visible.

## How sure we are

- Measured on the installed binary with payloads recorded from Claude Code 2.1.303 on this
  machine. The git operations ran directly between the Pre and Post payloads rather than
  inside an agent's shell. The recorder sees only the working tree and HEAD, so the order
  of events is what it would see.
- One file and one commit per scenario. Rebases, merges with conflicts and amended
  commits are not covered. Amending a commit made during the session keeps HEAD a
  descendant of the base. Amending the base commit itself does not, and would make the
  rest of the session unobservable. Neither case was run.
- Codex `apply_patch` sessions are not covered here; B1's tests cover the matcher.

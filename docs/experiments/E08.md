# E08: how many structured decisions do agent sessions produce for S3 to ask about?

## Why this matters (30 seconds)

S3 (design 03 section 4.6) quizzes the owner on decisions they made through the agent's
AskUserQuestion and ExitPlanMode calls. A typed answer in free text cannot be scored
without a judge, so these two tools are the only supply. If the owner's sessions rarely
call them, S3 is counts only, and the pilot should not spend probe time on it. Design
4.6 counted 0 of 241 tool uses in one transcript.

## Decision rule, written before the run (2026-10-19)

This runner measures supply and decides nothing about the owner. The population the S3
minimum is judged on is the owner's machine during the pilot, through derive.py's S3
rule (preregistration 1.7). On any other machine the result is a count of that machine's
sessions and is reported as such. The runner passes when every file in the population is
read (an unreadable file is counted, never skipped) and these are printed:

- `tool_use` blocks by tool name, main thread and sidechain apart, over
  `~/.claude/projects/*/*.jsonl` (design Q3's population) and, separately, every
  `*.jsonl` below `~/.claude/projects`, subagent transcripts included;
- for each main-thread structured decision, whether `praxis.transcript.read` can score
  it (one question, `multiSelect` false, string labels) and whether the chosen index was
  recovered;
- the time span each population covers, so that a rate per 30 days can be stated, and
  the human-typed prompts (`origin.kind == "human"`).

## What we did

`experiments/E08/decision_supply.py` on this machine's `/root/.claude/projects`. Only
tool names, counts and timestamps are kept in memory as results. No prompt, option label
or tool input is printed or written.

## What we measured

| Population | Files | tool_use blocks | Span | Human prompts | AskUserQuestion | ExitPlanMode |
|---|---|---|---|---|---|---|
| `*/*.jsonl` (Q3) | 1 | 394 | 0.92 days | 21 | 0 | 0 |
| `**/*.jsonl` (with subagents) | 33 | 1784 | 0.93 days | 21 | 0 (0 sidechain) | 0 (0 sidechain) |

No file was unreadable, and no line was malformed. Main-thread tools: Bash 209, Edit 90,
Write 36, Read 20, Agent 8, and 13 other names under 8 calls each. The sidechain adds Bash
857, WebSearch 195, WebFetch 130 and Read 98. The rate per 30 days is 0 in both
populations. **The runner passed**; the measurement is zero supply on this machine.

The population is the live transcript of the orchestration session that is building
this wave, so it grew while it was counted. The counts are for the moment of the run,
2026-10-19.

## What it means

- On this machine, S3 has nothing to ask about. That says little about the owner. This
  machine's one session is a cloud container driven by an orchestration script, whose
  agents dispatch subagents and write code without asking the human to choose between
  options. An interactive session on the owner's laptop is a different population. The
  owner's machine is the population that decides, through derive.py's S3 rule, in the
  pilot.
- The design's earlier measurement (0 of 241) and this one (0 of 394 on the main thread)
  agree. Neither population is the owner's interactive work. Two zero counts from
  non-representative sessions do not make an estimate.
- The transcript reader recognised 21 prompts as human-typed here. Wave 1 recorded none on
  CLI 2.1.257, which did not write `origin`. On the CLI that wrote this transcript, the
  segment and R1 code paths that need `origin.kind == "human"` have input.

## What we rejected

- Counting assistant text with numbered lines as decisions. Design 4.6 rejected it:
  telling offered options from steps needs a judge.
- Treating zero here as zero for the owner. Absence on one machine is not absence in the
  population, so the count is reported as this machine's, and S3 stays in the pilot.

## How sure we are

- The counts are exact for the files read, and they are not a sample of the owner's work.
- Whether AskUserQuestion was available to the agents in this environment at all is not
  recorded in the transcript. If it was not offered, the zero is structural rather than
  behavioural. Nothing on disk tells the two apart here.
- No Codex rollout exists on this machine (`~/.codex` absent). Codex has no documented
  AskUserQuestion equivalent (design 4.6), so S3 is unobservable for Codex either way.

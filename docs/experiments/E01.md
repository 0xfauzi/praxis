# E01: is telltale fit to be praxis's recorder, or does praxis record for itself?

## Why this matters (30 seconds)

Phase 0 wrote "the recorder is telltale" into AGENTS.md on the strength of telltale's own
documentation and test count. The policy layer and the drill generator both depend on
knowing which lines the owner wrote and which the agent wrote. If the recorder cannot
yield that, nothing above it can.

## Decision rule, written before the run (2026-10-18)

Six requirements, stated first:

- R1 captures a plain `claude` or `codex` session without a launcher wrapper.
- R2 yields attribution-grade edit data: enough to split a diff into agent and human parts.
- R3 answers inside the hook path quickly enough that the policy hook never times out.
- R4 makes a session joinable to its transcript file.
- R5 can be changed for attribution and Codex verification at a cost below rebuilding the
  part praxis needs.
- R6 is proportional in size to what praxis uses.

Rule: if telltale fails R1 or R2 on measurement, or the praxis-native alternative meets R1
to R4 in under a tenth of telltale's size on its first ugly build, praxis gets its own
recorder and telltale becomes an optional import source, not a dependency.

## What we did

1. A code map of telltale's edit, snapshot and attribution surface, with file:line
   citations, by a read-only subagent (R2, R5).
2. `telltale setup claude --print` and `telltale daemon --help` (R1).
3. `experiments/E01/receiver_latency.py`: the real Receiver over a real Store in a
   temporary home, the recorded S1 session replayed once to warm it, then its six
   PostToolUse bodies posted 200 rounds each (n=1200), wall-clock percentiles (R3).
4. Cold-start timing, five runs each, `date +%s%N` around the call: `telltale --help`;
   `python3 -I -c "import sqlite3, json, hashlib, sys"`; the same plus one sqlite open,
   insert and commit on a cold file (R3 for a command hook).
5. `git diff --unified=0 HEAD` and `git status --porcelain`, three runs each, on the
   telltale checkout (652 tracked files) and the praxis-v0 checkout (361) (R3 for the
   alternative).
6. `wc -l` over telltale's source by concern (R6).
7. `experiments/E01/attribution_proof.py`: the real PostToolUse Edit body from telltale's
   S1 fixture, its `originalFile` committed in a fresh repository, the edit applied, and
   `git diff -U0` runs matched by sha256 of changed lines against the same hash of the
   body's `structuredPatch` runs. Three scenarios with expected counts written in the
   script before it ran; the script exits 1 on a miss.

## What we measured

**R1.** A plain session is recorded only if the owner pastes a settings snippet (eight
env vars and twelve http hooks to 127.0.0.1:47311) into global settings and keeps
`telltale daemon` running. Telltale refuses to write the snippet itself.

**R2.** The Edit PostToolUse body carries `structuredPatch` (unified hunks),
`originalFile` and `userModified`. Telltale's parser copies only `command`, `file_path`,
`git_commit_id`, `subagent_type` and `description_length` out of tool input and only
`gitOperation.commit` out of tool response (providers/claude.py:614-663); the sanitizer's
`NEVER_PERSIST` drops `tool_response` and the Edit strings at any depth (sanitize.py:67-74);
the allowlist admits neither (allowlist.py:613-626). Snapshots store per-file patch hashes,
never hunks (repo.py:385-397, 436-448), fire only on agent tool calls with a 2 s debounce
and no maximum delay (launch.py:75; repo.py:470-472), never on a human edit, never on a
Bash write (commands.py classifies `sed` as `shell`, `tee`/`cp`/`mv` as `unknown`). Spec
12.4's `attribution: ambiguous` has no caller (`grep -rn "overlaps(" src` finds the
definition only). No human actor exists in the design (01-design.md:71). The fixtures
contain no Write, MultiEdit or NotebookEdit call in any of S1 to S8.

**R3.**

| Measurement | Result |
|---|---|
| Receiver POST, PostToolUse body, n=1200 | p50 1.44 ms, p95 1.97 ms, p99 2.40 ms, max 6.30 ms |
| Full S1 replay, 56 records, warm-up | 104.4 ms, all 200 |
| `telltale --help` cold, 5 runs | 161, 165, 167, 168, 169 ms |
| `python3 -I` + sqlite3/json/hashlib, 5 runs | 27, 29, 32, 36, 49 ms |
| same + open, insert, commit, cold file, 5 runs | 29, 32, 36, 36, 39 ms |
| `git diff -U0 HEAD`, 652 files, 3 runs | 6, 5, 5 ms |
| `git diff -U0 HEAD`, 361 files, 3 runs | 16, 4, 4 ms |
| `git status --porcelain`, both | 8 ms |

**R4.** Telltale stores `transcript_path` sanitized to `<outside>/<8 hex>` and the importer
stores a sha256 of the path. The join goes through the session UUID and a glob of
`~/.claude/projects` either way.

**R5.** Attribution inside telltale touches the parser, the persistence rule, the
allowlist, repo.py, the trigger set and the design document, under a brief-and-report
protocol built for an orchestrator dispatching implementers.

**R6.** 36,233 lines of source; 30,515 without the forecasting lab; 4,719 in the capture
core (receiver, store, sanitize, allowlist, activities); 2,932 in providers.

**R2 for the alternative** (`attribution_proof.py`, 150 lines including the harness):

| Scenario | Expected | Got |
|---|---|---|
| agent edit only | agent 1, human 0, ambiguous 0 | as expected |
| agent edit, owner changes `add()` and appends a function | agent 1, human 2, ambiguous 0 | as expected |
| owner alters a line inside the agent's hunk | agent 0, human 0, ambiguous 1 | as expected |

The first run of scenario 2 failed with one run instead of three: the script stripped `@@`
lines, which with `--unified=0` are the only separator between hunks. Keeping them fixed
it. That was a defect in the harness, not in the mechanism, and it is recorded here because
the fixed script is the one that ran.

## What it means

Telltale fails R2 by design, not by omission: three independent gates drop the data, and
the design document forbids keeping it. Meeting R2 inside telltale means changing what it
is. The alternative met R2 on real recorded data in 150 lines, with a hook-path cost of
about 40 to 60 ms per invocation against a 30 s limit. The rule says praxis records for
itself. It does.

The receiver's 1.44 ms is a real strength that praxis cannot use: the policy hook must run
a process to decide anything, so its floor is the 27 to 49 ms process start, not the POST.

## What we rejected

- Hunk-level matching (what the proof used). Hunks merge when edits touch adjacent lines
  and move when edits land nearby. The recorder uses line-level multisets instead
  (docs/design/01-recorder.md).
- Reading `structuredPatch` as the source of the agent's delta. It exists for Edit only.
  The recorder snapshots before and after every mutating tool call, so Write, MultiEdit,
  NotebookEdit and Bash writes fall out of one mechanism.
- Set matching. The proof's `attribute()` used sets, so two identical agent hunks in one
  file would have counted as one. AGENTS.md invariant 13 now forbids this and the recorder
  counts multisets.
- Keeping telltale as a dependency for the measures it does compute well (verification
  runs, compactions, tokens). Those remain reachable as a read-only join on session id when
  its store is present, which costs praxis nothing when it is absent.

## How sure we are

- R2 failure: measured (code map with citations, fixture inspection).
- R3 numbers: measured on this container; the owner's machine needs its own run.
- Alternative meets R2: measured on one Edit body from one fixture; Write, MultiEdit,
  NotebookEdit and Bash writes are reasoned from the mechanism and are what the
  integration suite tests with constructed edits, since no recording of them exists.
- Per-hook cost: first reasoned as 40 to 60 ms from the component timings, then measured
  with `experiments/E01/hook_cost.py` after the recorder was built: 100 invocations of the
  installed binary, wall clock p50 71.5 ms, p95 92.3 ms, max 100.5 ms; the hook's own
  work inside the process p50 8 to 12 ms. The reasoned figure was low by about 15 ms,
  which is the package import cost the component timings did not include. The owner's
  machine needs its own run; the hook_events table records it.
- R1 for the alternative: reasoned. Praxis needs its hooks in global settings for the
  policy layer anyway, so capture rides the same consent.

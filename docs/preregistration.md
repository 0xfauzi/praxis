# Pre-registration

Status: DRAFT, Stage 1 not yet frozen. No task, probe or forecast row exists. Stage 1
(pilot) must be complete before the first such row is stored, and Stage 2 (confirmatory,
generated by experiments/prereg/derive.py) before the first randomized task (AGENTS.md
invariant 11). Measurement design: docs/design/03-measurement.md.

This file is Stage 1. It fixes what the pilot collects and for how long, the design
choices the pilot runs under, the parameters `derive.py` will set and from what, every
validity check with its threshold and the plan it triggers, and the rule that pilot data
never enters a confirmatory test (design section 9). Stage 2 is written later by
`derive.py` from the pilot data and committed before the first randomized task; section 2
fixes its frame now. After Stage 1 is frozen, every edit to this file says why in the same
commit, and the amendment log at the end records it.

## 1. Stage 1: the pilot

### 1.1 The questions the study will answer

The pilot answers neither question. It exists so that Stage 2 can answer them with
parameters fixed from measurement.

- Q1 (instrument): does predicting before the agent acts (a component forecast plus
  prequestions on items bound to the task by a rule identical across arms) lower the
  owner's delayed, unassisted Brier score on those structural items, against registration
  with the same feedback and no prediction?
- Q2 (policy, after Q1's validity checks pass): does running the agent in a per-prompt
  mode change P1 on the components the policy fired for?

### 1.2 Design

- Single participant. Q1: task-level randomization inside `praxis task`, P(treatment) =
  0.5 (design choice), seed committed in Stage 2; general effect by a multiple baseline
  across at least 3 repositories with randomized start weeks (Koehler-Levin), descriptive
  only if fewer repositories are active. Q2: an allocation whose smallest attainable p is
  below alpha (unrestricted 4-of-8, at least 12 pair-blocked weeks, or multiple baseline);
  8 pair-blocked weeks are withdrawn (minimum p 0.0625).
- Pilot under Stage 1, with no randomization; the first pilot week is practice and never a
  floor; pilot data never enters a confirmatory test.
- Carryover is assumed, not tested away: learning does not wash out.

### 1.3 What the pilot collects, and for how long

Duration: three calendar weeks from the first registered task (a design choice). Week 1 is
format practice. An extension is an amendment, logged with its reason before it starts.

Prerequisite: the recorder fixes of design section 5 (apply_patch, base-sha diffing,
prompt_id and turn_id, edges at Stop) are installed before the first pilot row. Nothing
recorded before them is pilot data.

Every pilot task runs the treatment procedure (the F1 forecast over r sampled components
and k_e prequestions); there is no arm draw. Collected, in every repository with a frozen
component map:

- Recorder rows: snapshots, agent deltas, attributions, edge history at Stop, decision
  pointers, hook latency.
- Component maps and pool supply: `praxis components freeze` and `praxis components` per
  repository.
- Tasks: registration time, sampled components, F1 forecasts, prequestion answers, the
  bound, related-untested and drawn-not-shown items, flags, seconds spent, abandonment.
- P1 probes: every first probe of an exposed item, with response time, deadline result,
  truth, coverage and the attached-agent result; a validation-only set probed twice, 7
  days apart (V1); a validation-only comparison of L = 2 against L = 7 days (Q9 of the
  design).
- S1 drift probes weekly, S2 boundary rules and divergences, S4 removals, S3 decision
  pointers and responses where structured decisions occur, K knockouts for V7. C1
  Pathfinder runs are stored as PFSIM and PFSIM minus chance against the X1 referent,
  with the component count (`scoring.pfsim`, which replaced the unchecked closeness
  formula of design Q13); the ratings themselves are discarded.
- V3: one pilot week of the owner's real changes labelled by hand at their own grain.
- Owner-machine measurements, reported by `praxis doctor` and the pilot: repositories
  active per week, structured-decision supply, empty-segment rate, Codex payloads. Nothing
  is blocked on them.

### 1.4 Design choices fixed here

These are choices, not measurements. Stage 2 restates them; `derive.py` changes one only
by the rule committed with it, and the change is logged.

| Parameter | Value | Source |
|---|---|---|
| Probe lag L | 7 days | Richland, Kornell and Kao Exp 4 one-week delay (design 4.1) |
| Latest probe L_max | 28 days | design choice (design 4.1) |
| P(treatment) | 0.5 | maximizes contrast for a fixed task count (design 6.1) |
| Region size h | 3 components | design 6.2 |
| Bound items k_e | 2 per task | design 6.2 |
| Related-untested items k_r | 1 per task | design 6.2 |
| Drawn-not-shown items k_p | 1 per task | design 6.2 |
| Sampled forecast components r | 5 per task | design 4.4 |
| Probe deadline | 60 seconds per item, provisional | replaced by `derive.py` from the pilot response-time distribution |
| alpha, specific contrast | 0.05, one-sided | design 6.3 |
| Incongruent share of bound and held-out items | one half | design 8, V5 |
| R1 prior | (k + 1) / (n + 2) | design 4.4 |

Two extractor decisions are also fixed here. X1 static-import validity is assumed: dynamic
imports (`importlib`, `__import__`, string registries, `if TYPE_CHECKING`) are counted as
blind spots per component and make the items involving that component `partial`. Agent
predictability is not replayed: the published SWE-bench run-to-run coefficient of
variation (15.2 percent for Claude 4.5 Sonnet, 47.0 percent for Llama-3.1-70B, Mehta 2026,
cited in design 8) stands as the prior.

### 1.5 Metrics and definitions

Grid {0.1, 0.3, 0.5, 0.7, 0.9}; Brier per item; skill against references fitted on prior
data only (R_base, R_layer, R_fam for P1; R1, R0, R_last for F1), NULL until fitted;
Murphy decomposition with the Ferro-Fricker correction; CORP diagrams, bins read only at
81 or more forecasts; component map frozen per repository before its first task,
versioned, never pooled across versions; unassisted means the attached-agent check passed
and the item deadline was met. Stage 2 fixes, each from derive.py and starting from the
values in 1.4: L, L_max, deadlines, r, k_e, k_r, k_p, h, windows W and W_d, the survival
threshold, the exclusion cap and minimum counts. No Glicko-2, Elo or Rasch: one respondent
cannot identify item difficulty.

### 1.6 Parameters `derive.py` sets, and from what

`experiments/prereg/derive.py` is committed with this file, before the first pilot row. It
reads pilot weeks 2 and 3 only and maps them deterministically to:

| Parameter | Pilot input |
|---|---|
| L (only if changed) | the L = 2 against L = 7 comparison on validation-only items |
| L_max | `probe_missed` rate by lag |
| Probe deadlines | per-item response-time distribution |
| Binding and preview window W | registration-to-prompt gap distribution |
| Detection-latency window W_d | time from agent addition to removal (S4) |
| Decision survival threshold | multiset survival of the following prompt's agent hashes (S3) |
| Cut points (co-touch median for V5, familiarity buckets for S1) | co-touch distribution on data before each item |
| R1 burn-in | R1's leave-one-out Brier against the count of earlier segments |
| Exclusion cap | contamination-flag rate (`agent_previewed`, `late_prediction`, `version_change`) |
| Minimum counts (per-week reporting, S3 supply, sessions per week) | weekly counts of tasks, probes, decisions and sessions |
| Validity thresholds marked "set by derive.py" in 1.7 | the pilot statistic named in each row |
| Simulated minimum detectable Delta_spec and task counts | per-item Brier SD, ICC of forecasts within a task, between-week SD, lag-1 autocorrelation (the Shadish et al. 2013 prior until the owner's value replaces it), registration rate, skip rate, pool supply |

The rule `derive.py` applies to each input is part of the committed script, so no
threshold is chosen after the pilot data is seen.

### 1.7 Validity checks

No statement about the owner's understanding is made from any measure until these have run
on the pilot and the results are committed.

| Check | What | Threshold | Plan it triggers |
|---|---|---|---|
| V1 reliability | Split-half (odd and even items, Spearman-Brown) of P1 Brier per week; test-retest on the validation-only set | floor set by derive.py from the pilot | Below the floor: no P1 trend is reported |
| V2 extractor validity | X1 edges against runtime imports | not a gate | X1 validity is assumed (1.4); experiment E10 is dropped. Kept as a possible later check |
| V3 map agreement | Hand labels for one week against the mechanical map | set by derive.py from the pilot | Low agreement: freeze an owner map before Stage 2, never change a map afterwards |
| V4 agent predictability | Footprint agreement for identical prompts | not a gate | E09 replays are not run; the SWE-bench prior stands (1.4); footprint variance is reported from the pilot's own repeated prompts if any occur |
| V5 understanding against familiarity | BSS against R_fam and R_layer on incongruent D1 items | the interval of incongruent BSS against R_fam excludes zero; the congruent-accuracy level set by derive.py | See 1.8 |
| V6 known groups | Within one repository, P1 BSS against R_layer on owner-written components the agent restructured against owner-written components it did not touch; also between repositories by human share of attributed lines | higher on the untouched components, as predicted before the run; the between-repository check is necessary, not sufficient | See 1.8 |
| V7 convergence | Per component, P1, K and (after design Q13) C1 rank-correlated; per repository and week, F1 BSS_R1 against P1 BSS | power computed from pilot variance first | An underpowered null is reported as uninformative; a powered null is reported as one |
| V8 F1 skill | BSS_R1 and the task-shuffle placebo | BSS_R1 interval excludes zero; the true pairing's BSS_R1 exceeds the 95th percentile of the shuffled distribution | See 1.8 |
| V9 feasibility | Pool supply, registration rate, skip rate, cost | simulated minimum detectable effect at most the g = 0.28 equivalent; daily median of task plus probe time at most ten minutes | See 1.8; above ten minutes, redesign before Stage 2 |

#### Interval level for V5 and V8 [proposed, needs owner decision]

A 90 percent two-sided percentile interval by cluster bootstrap over tasks, because
forecasts within a task are not independent. B = 2000 resamples, seed committed in Stage
2. "The interval excludes zero" is then the one-sided test at alpha 0.05, the level fixed
in 1.4, so the validity checks and rule PR-1 use one error rate.

#### Rules derive.py applies [proposed, needs owner decision]

Each rule is a function in `experiments/prereg/derive.py`. It reads pilot weeks 2 and 3
only: from 7 to 21 days after the first registered task. A rule whose minimum input is
missing prints None with its reason. The 1.4 value then stands where the table says so,
and otherwise the parameter stays unset in Stage 2. No rule falls back to a default.
`derive.py --selfcheck` checks every rule on a pilot planted by hand.

| Parameter or threshold | Rule | Minimum pilot input |
|---|---|---|
| L | 2 days only if the split-half reliability (days as groups) of first-probe Brier at lags under 7 days is at least 0.10 above that at 7 days or more; otherwise 7 stands. probe.py has no short-lag mode yet, so as built this rule leaves L at 7 | 3 days with 2 or more probes in each lag group |
| L_max | the smallest of 14, 21 and 28 days at which at most 10 percent of the exposed items that old were never probed within it (a skip is a probe); none of them means infeasible (V9) | 20 exposures old enough |
| Probe deadline, per relation | the 90th percentile (nearest rank) of seconds over answered first probes, rounded up to 5 s; otherwise the provisional 60 s stands | 30 answers |
| W | the 95th percentile of registration-to-bind seconds, rounded up to the minute | 10 bound tasks |
| W_d | the 95th percentile of agent-addition-to-removal seconds, rounded up to the hour; each removed copy of a line pairs with the earliest unpaired added copy of the same line in the same file; a removal of a line the agent never added is not an S4 event | 30 removals |
| Decision survival threshold | Otsu's two-class cut over the decisions' survival fractions (the share of the following prompt's agent lines that survive to the session's last boundary, by multiset) | 10 decisions with 2 distinct fractions |
| Co-touch cut (V5) | per item, on closed tasks before its exposure: the median co-touch share over product pairs that both have outcome rows; a share at the median is low | none: a rule, applied at analysis time |
| Familiarity buckets (S1) | never co-touched; at or below the median nonzero co-touch share; above it | none: a rule |
| R1 burn-in | the start of the first block of 5 earlier-segment counts whose mean leave-one-out R1 Brier improves on the next block's by at most 0.01 | 10 pilot tasks whose bound prompt is found in its transcript |
| Exclusion cap | the one-sided 95 percent Wilson upper bound of the share of pilot tasks flagged `agent_previewed`, `late_prediction` or `version_change`, rounded up to 0.01 | 10 tasks |
| N, sessions per week (2.5) | half the mean weekly session count of pilot weeks 2 and 3, rounded down | 1 session |
| Minimum probes per week | the count that gives a 95 percent half-width of 0.10 Brier at the pilot's per-item SD | 30 first probes |
| S3 minimum decisions | the count that gives a 95 percent half-width of 0.10 on recall accuracy at the pilot's accuracy; below the minimum input S3 is counts only | 10 decision responses |
| V1 floor | split-half reliability at least 0.70. Days stand in for weeks, because two pilot weeks cannot give the 3 groups a split-half correlation needs | 3 days with 2 or more probes |
| V3 threshold | Cohen's kappa at least 0.60 between the hand labels and the mechanical map | the V3 hand labels, which the ledger does not hold |
| V5 congruent-accuracy level | "high" when the lower end of the congruent BSS-against-R_base interval is above zero | as V5 |
| Q1 re-draw rule | arms are drawn Bernoulli(0.5) per task. `scoring.randomization_test` re-draws with the treated count fixed at its observed value. Given the count, every allocation of that size is equally likely under the Bernoulli rule, so the conditional test is exact and therefore valid unconditionally | none |
| Power counts (1.6) | simulation through `scoring.randomization_test` of per-task mean Brier over answered bound items. Week effects are AR(1) over lag-1 values {-0.2, 0, 0.2}, because two pilot weeks cannot estimate it. A task effect gives the measured ICC, and an ICC below 0 is simulated as 0. Arms are Bernoulli(0.5). 200 simulated studies, 200 draws each, seed 20261019. The Stage 2 count is the largest over the lag-1 grid, at 80 percent power and one-sided alpha 0.05 | per-item SD (30 probes), ICC (10 tasks with 2 bound answers), between-week SD (2 weeks of 5 or more probes), registration rate, answer rate (bound items giving a primary observation over bound items probed or past L_max unprobed; 10 such items), pool supply |

### 1.9 Pilot data never enters a confirmatory test

No pilot row is an observation in any Stage 2 test, estimate or decision rule. Pilot data
sets parameters through `derive.py` and nothing else. An item exposed or probed in the
pilot is consumed and is re-admitted only when its truth flips (a new epoch, design 3.5).
Validation-only items are excluded from every confirmatory analysis. Week 1 is never used
as a floor or a baseline.

## 2. Stage 2: confirmatory (generated by derive.py, not yet written)

Stage 2 is generated by `derive.py` from the pilot and committed before the first
randomized task. It fixes the outcomes, estimands, allocation, tests, alpha, seeds,
exclusions and decision rules. The frame below is fixed now; Stage 2 fills its numbers and
may narrow it, never widen it.

### 2.1 Outcomes

Primary (Q1): Delta_spec, mean Brier of first delayed P1 probes on bound items in control
tasks minus treatment tasks, items with unchanged truth and deadline met. Secondary, in
this order and no others: (1) near transfer, the same contrast on related-untested items;
(2) untargeted effect, the same contrast on drawn-not-shown items; (3) general effect,
multiple-baseline level change in never-exposed P1 Brier; (4) F1 forecast skill over R1;
(5) S1 drift-notice skill; (6) S2 caught share (associative); (7) task and probe
completion rates; (8) substitution rate by judge, deferred until a judge exists. Q2
primary: P1 on components the policy fired for.

### 2.2 Thresholds and decision rule

Rule PR-1 (Q1): the instrument is said to have changed delayed structural accuracy on
bound items only if the one-sided randomization test of Delta_spec (per-task mean Brier as
the unit, arms re-drawn under the actual allocation rule, seed and draw count committed)
gives p below alpha (0.05, fixed in 1.4), the pipeline placebo does not differ from zero,
and V1, V5 and V6 passed in the pilot. The minimum detectable Delta_spec is written here
from simulation through this exact test using pilot per-item SD, ICC, between-week SD,
lag-1 autocorrelation, registration rate and item supply; a repository whose supply cannot
reach the simulated count is excluded from the confirmatory analysis. Rule PR-2 (Q2) is
written in Stage 2 in the same form. A report that meets a rule may say changed under rule
PR-1 (or PR-2); cause, impact and would stay refused.

### 2.3 Signal admission (calibration)

A behavioural signal may enter any report or policy decision only if:

- Fit on the first half of available weeks, it predicts the held-out second half's P1
  score per component with a correlation whose confidence interval excludes zero. Stage 2
  fixes the interval level and the minimum number of held-out weeks.
- It fails to predict P1 scores on shuffled week labels (the placebo in 2.4).

Admission is a commit that cites both results. A signal that later fails on new weeks is
removed by a commit that cites the failure.

### 2.4 Placebo and permutation

- Placebo: every calibration and every primary analysis is repeated with labels shuffled
  (seeded, exact enumeration when there are 70 or fewer allocations, otherwise Monte Carlo
  with a committed draw count, seed committed in Stage 2). A result that is not
  distinguishable from the shuffled distribution is reported as such. The placebos:
  drawn-not-shown against never-drawn items; F1 forecasts shuffled among tasks; component
  labels permuted on the truth graph.
- Randomization test for each primary outcome: the observed contrast against its
  distribution under re-drawing the allocation by the rule actually used (tasks for Q1,
  start weeks for the general effect, the Stage 2 allocation for Q2).

### 2.5 Exclusions, fixed before data

- Weeks with fewer than N sessions are excluded from the primary analysis. N is set by
  derive.py from the pilot's session counts.
- A probe answered with an agent attached is void and is logged, and the refusal counts
  against probe completion rate.
- Tasks flagged agent_previewed, late_prediction or version_change are excluded from F1 up
  to the pre-registered exclusion cap, beyond which they form a sensitivity stratum; items
  answered after their deadline are excluded from the primary.

### 2.6 What this design can and cannot show

It can show whether this participant's delayed structural accuracy on bound items differed
between tasks in which they predicted and tasks in which they did not, and, for Q2,
whether P1 moved differently under the policy, each under its rule. It cannot show an
effect size for anyone else. Task-level randomization estimates the effect of being asked
to predict; the effect of probing itself is applied equally to both arms and cannot be
estimated. The protocol in 2.7 is how the first limitation is addressed over time.

### 2.7 Protocol

The instrument, this file and an anonymized export schema (strips paths, identifiers and
code; keeps per-week metrics and scores) are published so that another person can run the
same pilot and confirmatory study on their own machine and produce comparable rows.

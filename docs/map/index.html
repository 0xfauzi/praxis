  1. A praxis hook exits 0 on every input and never changes the output or exit code of the agent. Its stdout is empty, except one fixed terminalSequence notice, recorder.NOTICE, at the Claude Code Stop that closes a registered task segment (AGENTS.md, invariant 7; src/praxis/hooks.py docstring and _notify; src/praxis/recorder.py NOTICE).examined · current
  2. Only src/praxis/store.py contains INSERT statements for the ledger tables. The derived-writes-only-in-store pre-commit hook refuses them in other modules (AGENTS.md, invariant 2; .pre-commit-config.yaml).examined · current
  3. The ledger stores hashes, counts, and identifiers. It never stores a line of a file, a prompt, or a tool input or response. A scenario argv is stored only as a hash (AGENTS.md, invariant 5; src/praxis/schema.py docstring; src/praxis/scenarios.py docstring; docs/design/01-recorder.md, What is stored).examined · current
  4. Without a baseline, the human, pre-existing, and reverted counts are NULL and the coverage is no_baseline. A CHECK constraint keeps the two together (AGENTS.md, invariant 4; src/praxis/schema.py:162-165).examined · current
  5. Attribution matches multisets of line hashes: two identical lines are two lines, and an agent line that the diff no longer holds is ambiguous, not human (AGENTS.md, invariant 13; src/praxis/gitdiff.py docstring).examined · current
  6. praxis setup PRINTS the hook block. With --apply or --remove, it writes exactly one named file after an interactive yes, and it refuses when stdin is not a terminal (AGENTS.md, invariant 8; src/praxis/install.py:195-203).examined · current
  7. praxis doctor never creates the ledger and counts its rows in SQLite read-only mode. It asks probe.due for probes due only when the ledger is at SCHEMA_VERSION, so the Store that probe.due opens runs no migration. The scenario summary that it prints opens a Store only at SCHEMA_VERSION too (src/praxis/doctor.py docstring, _ledger_state, and _due; src/praxis/scenarios.py summary and _last_runs).examined · current
  8. The dependencies list in pyproject.toml is empty. Praxis uses the Python standard library only (AGENTS.md, invariant 6; pyproject.toml line 15).examined · current
  9. Code that must run for a measurement runs in a scratch clone under $PRAXIS_HOME that the caller deletes. The working tree and .git of the owner are never written. praxis scenarios run gives each scenario its own clone and deletes it after the scenario, also on failure. PRAXIS_HOME points into the clone (AGENTS.md, invariant 5; src/praxis/extract.py scratch_clone docstring; src/praxis/scenarios.py docstring and _run_one).examined · current
  10. Probe items are scored by deterministic, versioned extractors. No project test is a score or an item source (AGENTS.md, invariant 9; src/praxis/extract.py EXTRACTOR_VERSION and X2_VERSION).examined · current
  11. The attached-agent check looks for claude or codex processes with a working directory in the repository. Where /proc is missing, it counts any such process anywhere. praxis probe runs the check first, and when it finds an agent it records an agent_attached flag and asks nothing (AGENTS.md, invariant 9; src/praxis/unassisted.py attached_agents; src/praxis/probe.py docstring and _administer).examined · current
  12. praxis report writes nothing when its text holds the words cause, impact, or would and no pre-registered rule is met. The text names each rule with its result (AGENTS.md, invariant 3; src/praxis/render.py docstring, _REFUSED, and render).examined · current

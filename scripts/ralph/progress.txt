## Iteration 2 - US-010: Redact generic secret-like substrings
- What I did: Added _GENERIC_LABELED_SECRET regex `(?i)(\b(?:key|token|secret|password)\b\W*)[A-Za-z0-9_\-]{20,}` to praxis/redactor.py and wired it into the redaction pipeline with replacement `\1[REDACTED]` so the label + separator survive and only the high-entropy tail is redacted. Generalized _PROVIDER_PATTERNS into _PATTERNS as a tuple of (pattern, replacement) pairs so the new entry can carry its own backref-using replacement while redact_secrets() remains a single fold. Added 9 tests covering all four labels (key/token/secret/password), case-insensitive matching, short-value non-match, label-inside-word non-match, intervening-word non-match, and a self-test that two passes produce the same output.
- Files changed: praxis/redactor.py, tests/test_redactor.py, scripts/ralph/feature/secret-redaction/prd.json (US-010 -> passes:true).
- Verification:
  - uv run pytest -q  -> 54 passed (was 45; +9 new US-010 tests).
  - uv run mypy praxis/redactor.py tests/test_redactor.py  -> Success: no issues.
  - uv run mypy praxis  -> still 34 pre-existing errors in 6 files, zero new.
- What the next iteration should know:
  - Module-level pattern list is now `_PATTERNS: tuple[tuple[re.Pattern[str], str], ...]` (not `_PROVIDER_PATTERNS`). If US-011 wants to add another rule, append `(compiled_pattern, replacement_string)` to this tuple; the replacement may contain backrefs.
  - Idempotence (US-011) is already de facto preserved: provider regexes have no `[` in their char classes, and the new _GENERIC_LABELED_SECRET value class also excludes `[` (and the {20,} length defeats the 8-char `REDACTED` body), so a second pass over `[REDACTED]` cannot match. Verified by test_generic_does_not_re_redact_placeholder. US-011 should add an explicit `redact_secrets(redact_secrets(x)) == redact_secrets(x)` test (and probably one with multiple secret types in the same string) to lock this in, but no code change is needed unless that test fails.
  - The labeled-secret regex uses `\W*` (zero-or-more non-word chars) as the separator. This deliberately includes `\n`, so multi-line `key:\n  abc...` patterns are still redacted; but intervening English words (e.g., "password is wrong") break the match because the next `\w` stops `\W*` and the value class doesn't admit a leading letter-word. Keep this property when extending.
  - The literal alternation is exactly `key|token|secret|password` -- singular, no plurals, no compound forms like `API_KEY` (since `\bKEY\b` does not match inside `API_KEY`). If a future story wants to cover compound env-var names, that is a new requirement; do not silently widen this regex.

## Iteration 3 - US-011: Redaction is idempotent
- What I did: Added 6 tests at the end of tests/test_redactor.py that lock in idempotence: a per-pattern double-run check across all 6 entries in _PATTERNS, a mixed-secrets double-run check, and four placeholder-stability checks (bare placeholder, placeholder in prose, two adjacent placeholders, placeholder right after a label). No change to praxis/redactor.py -- idempotence was already a design invariant of the existing regexes (value classes exclude `[`, labeled-secret tail requires >= 20 chars > len("REDACTED")=8, and "REDACTED" is not a label literal); the new tests just assert it.
- Files changed: tests/test_redactor.py, scripts/ralph/feature/secret-redaction/prd.json (US-011 -> passes:true).
- Verification:

  - uv run mypy praxis/redactor.py tests/test_redactor.py  -> Success: no issues.
  - uv run mypy praxis  -> still 34 pre-existing errors in 6 files, zero new.
- What the next iteration should know:
  - All three feature stories (US-009, US-010, US-011) now pass. If the PRD has no further stories, the loop should terminate.
  - Idempotence is now a tested invariant, not just a design intent. If a future change to praxis/redactor.py adds a pattern, the new pattern MUST keep `[` out of its value class and its tail-length budget; otherwise test_bare_placeholder_is_unchanged / test_placeholder_in_prose_is_unchanged will fail loudly.
  - The "redaction is idempotent" property is what lets the rest of the pipeline call redact_secrets() defensively at multiple stages (e.g., on read, on write, on render) without risk of corrupting already-redacted text. Spec section 4.4 calls for this; future code that wires redaction into persistence/rendering paths can rely on it.

## Iteration 5 - US-042: Weekly buckets and per-bucket means
- What I did: Added praxis/behavior/weekly.py implementing the v0.2 trajectory model's first stage (PRAXIS_V0_2_SPEC.md section 7.2). Public API: `WeeklySessionInput` (started_at + engagement/delegation/independence rates + dim_scores dict), `WeeklyBucket` (iso_week tag, Monday week_start, session_count, three rate means, dim_score_means, eligible_for_fit bool), and `bucket_sessions_by_iso_week(sessions, *, now=None, window_days=90)`. Buckets are sorted oldest-first by `week_start`. Constants `DEFAULT_WINDOW_DAYS=90` and `MIN_SESSIONS_FOR_FIT=2` are exported. Naive datetimes are normalized to UTC; the cutoff is inclusive (sessions at exactly now-90d are kept). Buckets with `session_count < 2` are still returned but flagged `eligible_for_fit=False` so the cost-ledger render path can use them while the fit (US-043) skips them. Wired the new names into praxis/behavior/__init__.py.
- Files changed: praxis/behavior/weekly.py (new), praxis/behavior/__init__.py (export new names), tests/test_weekly_buckets.py (new, 13 tests), scripts/ralph/feature/trajectory-model/prd.json (US-042 -> passes:true).

- What the next iteration should know:
  - The next four stories (US-043 slope+stderr, US-044 label mapping, US-045 hysteresis, US-046 LLM headline) all build on the `list[WeeklyBucket]` produced here. US-043 should consume only the buckets where `eligible_for_fit` is True (spec 7.2 + 7.4) and fit a least-squares line over the per-bucket means in `week_start` order. The x-axis unit is "weeks since the earliest eligible bucket" (one unit per ISO week) so that the slope thresholds in 7.2 ("|slope| >= 0.05 per week") and 7.4 ("2.0 * stderr" for hysteresis) read directly. Do not re-bucket inside US-043; consume the existing buckets.
  - Public API surface to import from: `from praxis.behavior import WeeklyBucket, WeeklySessionInput, bucket_sessions_by_iso_week, iso_week_tag, iso_week_start, DEFAULT_WINDOW_DAYS, MIN_SESSIONS_FOR_FIT`. Names are also available from `praxis.behavior.weekly` directly. Keep them stable; don't rename in later stories.
  - WeeklySessionInput is deliberately decoupled from the v0.1 Session / BehavioralSignals / SessionScore types. When orchestrator wiring lands (a later spec-level concern, not in this PRD), the adapter from (Session, BehavioralSignals, SessionScore) -> WeeklySessionInput is a 4-line dataclass construction at the call site; don't try to merge WeeklySessionInput back into the older types or you'll re-create the coupling we just avoided.

The fit code in US-043 should iterate the dim keys present across the eligible buckets and skip any dim whose presence is too sparse, not assume every bucket has every key. The current 6 rubric keys are always present in well-formed SessionScores, so in practice every bucket should have all 6 - but the contract is "skip-not-invent" for robustness.
  - The ISO-week tag format is the exact spec format `YYYY-Www` with zero-padded week (e.g. "2026-W21"). This is the same key used in spec section 14 for `weekly_digests.week_iso` and `follow_ups.week_iso`. Reuse `iso_week_tag()` rather than rolling another formatter; mismatched formats will break the follow-up join in US-045+ and future schema work.
  - `bucket_sessions_by_iso_week` accepts an optional `now: datetime` for tests. Use this in US-045 tests when you need to assert stability across two "consecutive runs" on identical inputs - construct the buckets once with `now=t0`, run the labeler twice, assert no label change. The same `now=` parameter is how US-043/044 tests should pin the 90-day window.
  - There is NO mypy config at the project level; "typecheck passes" continues to mean "new files have zero mypy errors when run with --follow-imports=silent (or are zero-error from the perspective of the new file itself)". The 13 pre-existing trajectory.py errors are out of scope for this PRD; do not try to fix them.
  - Test fixture convention: tests build WeeklySessionInput directly with timezone-aware datetimes (timezone.utc) plus dim_scores built via `{k: value for k in RUBRIC_KEYS}` where `RUBRIC_KEYS = [d.key for d in RUBRIC]`. This avoids depending on Session / scanner fixtures from conftest.py and keeps the trajectory tests fast and decoupled.

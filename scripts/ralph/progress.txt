  - Patterns established:
    * `_read_hook_payload(stream, timeout_seconds=0.1)` is the seam for any future "read JSON from stdin within a timeout" need. It uses `stream.fileno()` to detect a real file descriptor and only enables select on POSIX; tests pass `io.StringIO` which has no fileno, so they bypass the timeout entirely and never flake on slow CI.
    * `_parse_hook_payload(raw)` rejects non-dict JSON (numbers, lists, strings) so unexpected JSON shapes go down the same "skip with missing-payload note" path as syntax errors. Don't relax this -- the duck-typing for Claude Code vs Codex relies on the result being a `dict[str, Any]`.
    * `_extract_session_id(payload)` is the single chokepoint that decides "do we have a valid session?" -- both shapes' required fields collapse to checking `session_id` because both providers name the field identically. If a third tool's hook lands and uses a different field name, add a fallback chain here rather than branching at the call site.
    * `session_stable_id` convention: on the happy path we use the parsed session_id verbatim; on degenerate paths we use `f"session-end:{week_iso}"` so the row is still attributable to the week even when the hook payload is broken. The "manual:<week>" prefix is reserved for US-024's interactive path.
  - Hooks for upcoming stories:
    * US-026 (threshold gating): The happy-path branch in `_cmd_reflect_session_end` currently writes `self_report='skip', note=None`. US-026 should slot the threshold check between `_extract_session_id` returning a session_id and the placeholder insert: if the transcript_path read shows < `[reflect] turns_min` user turns OR elapsed_seconds < `[reflect] elapsed_seconds_min`, change the note to `'session too short'` (keep self_report='skip'). If transcript_path doesn't exist on disk, note becomes `'transcript missing'`. The config accessor should reject negative values at load time -- consider adding `ReflectConfig` to praxis/config.py with a typed `load_reflect()` that raises on invalid input, mirroring how ScheduleConfig is handled.
    * US-027 (detached child): The happy-path branch is the seam to spawn a detached `subprocess.Popen` with `start_new_session=True` (POSIX) / `CREATE_NEW_PROCESS_GROUP` (Windows). Pass `--child --follow-up-id <id> --session-id <sid> --cwd <cwd> --transcript-path <path>` as explicit flags (no stdin, since stdin will already be drained by `_read_hook_payload`). The child re-enters `cmd_reflect` with `args.child` set, opens `/dev/tty` (POSIX) or CONIN$/CONOUT$ (Windows), and reuses `_run_interactive_reflect`. Reflect's exit codes should stay in {0, 1, 4} to avoid colliding with Claude Code's exit-2 "block" sentinel.
    * Argparse wiring for US-027: add `rfl.add_argument("--child", action="store_true", dest="child")` plus the four explicit flags above. The TTY-detection check is `sys.stdin.isatty()` on the parent; if isatty False, spawn the detached child instead of running interactively. Hook timeout for parent return is configurable; default to 5 seconds per AC.
  - Gotchas:
    * `select.select` on Windows only supports sockets, not file descriptors. The helper checks `sys.platform != "win32"` and falls through to an unconditional `stream.read()` on Windows. In practice the Stop hook closes stdin immediately after posting the payload so the read returns quickly, but if a future Windows-specific user reports the parent hanging, the fix is a thread-based read-with-timeout, not adding Windows select support.
    * `_cmd_reflect_session_end` is intentionally silent on no-active-commitment and on `MultipleActiveCommitmentsError`. The interactive path prints messages for those cases; the session-end path must not, since stdout/stderr of the hook process are visible to the AI tool and would either appear in transcripts or trigger the AI tool to treat the output as an instruction. If a future story needs to surface these failures, route them to a log file under `~/.praxis/`, not to stderr.
    * On the happy path we write `self_report='skip', note=None` with the real session_id as `session_stable_id`. Tests for US-026/US-027 should expect to OVERWRITE this row insert (not add a second row) -- the table has an autoincrement PK so two inserts for the same session_id would land as two rows, which would double-count the session. Either change the happy path to delete-then-insert, or move the insert to after the threshold gate (US-026) / detached-child decision (US-027). Today's behavior is "one row per --session-end invocation regardless of outcome"; US-026's `turns_min` check should still produce one row per invocation, just with a different note.
    * The Pyright "Code is unreachable" / "args not accessed" diagnostics on `praxis/cli/__main__.py` are pre-existing in other functions (not introduced by this iteration); verified via lint baseline. Don't try to "fix" them as part of reflect stories unless explicitly assigned.

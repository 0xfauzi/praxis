## Iteration 2 - US-010: Redact generic secret-like substrings
- What I did: Added _GENERIC_LABELED_SECRET regex `(?i)(\b(?:key|token|secret|password)\b\W*)[A-Za-z0-9_\-]{20,}` to praxis/redactor.py and wired it into the redaction pipeline with replacement `\1[REDACTED]` so the label + separator survive and only the high-entropy tail is redacted. Generalized _PROVIDER_PATTERNS into _PATTERNS as a tuple of (pattern, replacement) pairs so the new entry can carry its own backref-using replacement while redact_secrets() remains a single fold. Added 9 tests covering all four labels (key/token/secret/password), case-insensitive matching, short-value non-match, label-inside-word non-match, intervening-word non-match, and a self-test that two passes produce the same output.
- Files changed: praxis/redactor.py, tests/test_redactor.py, scripts/ralph/feature/secret-redaction/prd.json (US-010 -> passes:true).
- Verification:
  - uv run pytest -q  -> 54 passed (was 45; +9 new US-010 tests).
  - uv run mypy praxis/redactor.py tests/test_redactor.py  -> Success: no issues.
  - uv run mypy praxis  -> still 34 pre-existing errors in 6 files, zero new.
- What the next iteration should know:
  - Module-level pattern list is now `_PATTERNS: tuple[tuple[re.Pattern[str], str], ...]` (not `_PROVIDER_PATTERNS`). If US-011 wants to add another rule, append `(compiled_pattern, replacement_string)` to this tuple; the replacement may contain backrefs.
  - Idempotence (US-011) is already de facto preserved: provider regexes have no `[` in their char classes, and the new _GENERIC_LABELED_SECRET value class also excludes `[` (and the {20,} length defeats the 8-char `REDACTED` body), so a second pass over `[REDACTED]` cannot match. Verified by test_generic_does_not_re_redact_placeholder. US-011 should add an explicit `redact_secrets(redact_secrets(x)) == redact_secrets(x)` test (and probably one with multiple secret types in the same string) to lock this in, but no code change is needed unless that test fails.
  - The labeled-secret regex uses `\W*` (zero-or-more non-word chars) as the separator. This deliberately includes `\n`, so multi-line `key:\n  abc...` patterns are still redacted; but intervening English words (e.g., "password is wrong") break the match because the next `\w` stops `\W*` and the value class doesn't admit a leading letter-word. Keep this property when extending.
  - The literal alternation is exactly `key|token|secret|password` -- singular, no plurals, no compound forms like `API_KEY` (since `\bKEY\b` does not match inside `API_KEY`). If a future story wants to cover compound env-var names, that is a new requirement; do not silently widen this regex.

## Iteration 6 - US-018: Substring-verify every quoted_excerpt against the source transcript
- What I did: Added `verify_moment_substrings(session, moments)` to praxis/scoring/judge.py with two private helpers: `_normalize_whitespace(text)` collapses runs of `\s+` to a single space and strips ends, and `_session_corpus(session)` joins every turn.content with a single space. A moment survives iff the normalized excerpt is a substring of the normalized corpus; otherwise the moment is dropped and a `[scorer] moment failed substring check (dim=..., turn=...)` line is emitted to stderr. No fuzzy / approximate match fallback exists. Wired the verifier into both score_with_claude and score_with_openai (right after _parse_response) so every LLM-judge path runs through it before returning. Added 12 tests covering: exact-substring pass, whitespace-only-difference pass (tabs/newlines/runs of spaces), invented excerpt dropped with log line, one-character difference dropped (no fuzzy fallback), mixed pass/fail batch with exactly one log line per failure, empty input returns empty, assistant-turn excerpts accepted (Spec §4.1), excerpts spanning a turn boundary accepted, whitespace-only excerpt rejected (guard against `'' in transcript` always being True), log line includes dim_key and turn_index context, case-sensitive match (Spec §4.4 specifies whitespace normalization only, not case), and input-list non-mutation.
- Files changed: praxis/scoring/judge.py (verifier + wiring), tests/test_judge.py (12 new tests + Session/Turn/Provider/Role imports + _make_session/_make_moment helpers), scripts/ralph/feature/judge-moments-extension/prd.json (US-018 -> passes:true).
- Verification:
  - uv run pytest tests/test_judge.py -v  -> 27 passed (was 15; +12 new US-018 tests).
  - uv run pytest tests/  -> 87 passed (was 75; +12 new).
  - uv run mypy praxis/scoring/judge.py tests/test_judge.py  -> 5 errors, all the pre-existing TextBlock union-attr at the score_with_claude `block.text` line (now at line 377 since my insertions shifted it from 329; confirmed via `git stash --keep-index -u` + mypy that the 5 errors exist on main as well, just at line 329). Zero new errors.
  - Bad-patterns scan on changed .py files (ralph_py/verify.py SECRET_PATTERNS replicated locally) -> clean. No new fixture trips the scanner.
- What the next iteration should know:
  - Public API surface added: `from praxis.scoring.judge import verify_moment_substrings`. Signature is `(session: Session, moments: list[Moment]) -> list[Moment]`. Pure function, returns a new list, does not mutate input. Safe to call multiple times (idempotent on already-verified moments).
  - The verifier is now applied INSIDE score_with_claude and score_with_openai (right after _parse_response). This means any code path that goes through score_session (or calls those two functions directly) gets verification for free. US-020 (persistence) should NOT re-run verification: by the time a JudgeResult reaches the orchestrator / persistence layer, result.moments is already the substring-verified set. If a future story bypasses score_with_X (e.g. for replay testing), it must call verify_moment_substrings explicitly before persisting.
  - The corpus used for verification is `" ".join(turn.content for turn in session.turns)` -- ALL turns, regardless of role, joined with a single space. This is deliberate per spec §4.1 ("the assistant's words" can be quoted) and the spec's §9.2 distinction that "the moments excerpts still verify against the full transcript stored locally; the judge never sees the full one". Tool-call args and role markers are NOT in the corpus -- the judge prompt instructs the model to quote rendered text only, so an excerpt that quotes a tool name will (correctly) fail verification and get dropped.
  - Whitespace normalization is exactly `re.sub(r"\s+", " ", text).strip()` -- the simplest possible normalization that handles the realistic case (judge re-spaces multi-line quotes). Case is NOT normalized; the test `test_verify_case_sensitive_match` locks this in. If a future judge model proves to be sloppy with case in excerpts, that is a calibration problem to fix in the prompt, NOT a verifier change -- the spec's "Do not fall back to a fuzzy excerpt" is explicit.
  - The log line format is `[scorer] moment failed substring check (dim=<dim_key>, turn=<turn_index>)`. The prefix `[scorer] moment failed substring check` is the part the spec mandates; the trailing context is for debugging. If you grep for the failure in production logs, use the prefix. The `test_verify_log_line_includes_dim_and_turn_context` test pins both halves so future refactors don't silently strip the debug context.
  - Whitespace-only excerpt is explicitly handled: an excerpt that normalizes to an empty string is rejected, NOT silently accepted (Python's `"" in transcript` is always True, which would be a serious bug). The `test_verify_drops_whitespace_only_excerpt` test pins this.
  - US-020 path: the verifier returns a list[Moment] with the same Moment objects (same identity, no copy). When US-020 calls `dataclasses.replace(m, ...)` to add moment_id / session_stable_id / redaction flags, it operates on these survivor objects. No additional plumbing is needed between US-018 and US-020 -- result.moments is the persist-eligible set.
  - US-019 (confidence + confidence_reason): unrelated to the verifier. The verifier reads only `m.quoted_excerpt`; adding confidence fields to JudgeResult will not affect it.
  - Test helpers I added in tests/test_judge.py (`_make_session`, `_make_moment`) are file-private but reusable for future judge tests. If you need a Session fixture with multiple turns, follow the `[(Role.USER, "..."), (Role.ASSISTANT, "...")]` pattern; if you need a non-default Moment field, extend the keyword args of `_make_moment` rather than constructing Moment manually.
  - pytest capsys: the existing test file did not use any pytest fixtures (it tested pure functions). My new tests use capsys to assert on the log line content. The fixture is auto-injected by pytest; no import needed. The `# type: ignore[attr-defined]` on `capsys.readouterr()` calls is because the parameter annotation is `object` (since `pytest.CaptureFixture` would require importing pytest, and our static analyzer complains about the unused import).

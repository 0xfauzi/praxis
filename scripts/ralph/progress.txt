## Iteration 1 - US-047: Weekly spend and baseline
- What I did: Added praxis/scoring/cost_ledger.py with a pure aggregator (compute_cost_ledger) that sums per-session USD into a current-week total + a 90-day rolling weekly mean, plus a card-resolution helper (estimate_session_cost_usd) that mirrors models_advisor/advisor.py._estimate_cost. Backed by tests/test_cost_ledger.py (19 tests).
- Files changed: praxis/scoring/cost_ledger.py (new), tests/test_cost_ledger.py (new), scripts/ralph/feature/cost-ledger/prd.json
- Verification:
  - python -m pytest tests/test_cost_ledger.py -v -> 19 passed
  - python -m pytest -q -> all passed
  - pyright praxis/scoring/cost_ledger.py tests/test_cost_ledger.py -> 0 errors
  - mypy praxis/scoring/cost_ledger.py tests/test_cost_ledger.py -> 0 errors in the new files (pre-existing errors in advisor.py / aggregate.py / coach.py / cli/__main__.py are unrelated and were present before this iteration)
- What the next iteration should know:
  - The aggregator is pure: pre-computed `cost_usd` in, ledger out. No disk I/O. Card lookup is isolated to `estimate_session_cost_usd`, which calls `find_card_for_model_hint` (matches the advisor pattern). Tests of the aggregator don't need `tmp_home`; helper tests do.
  - Baseline rule: mean of per-ISO-week spend totals over weeks with at least one priced session. Quiet weeks are NOT zero-padded -- locked in by `test_baseline_excludes_zero_weeks`. Rationale: a user who took time off shouldn't see an artificially low baseline that makes every active week read as "over baseline".
  - `cost_usd=None` marks unpriced sessions (no card on file, or subscription-only models like Copilot whose pricing fields are null). They are skipped, not counted as zero, so the weekly total and the baseline both reflect "priced spend" only. `weekly_session_count` and `baseline_session_count` are priced-session counts. If a future story needs total-session counts (priced + unpriced), pull them from the orchestrator/cluster panel, not from CostLedger.
  - Window mirrors `praxis.scoring.baseline.compute_baseline`: `[as_of_date - 90 days, current ISO week Monday)`. Current ISO week is excluded from the baseline (same logic, same Monday boundary).
  - Cost-estimate constants (`COST_CHARS_PER_TOKEN=4.0`, `COST_OUTPUT_TO_INPUT_RATIO=1.5`) match `models_advisor/advisor.py._estimate_cost`. A future story that consolidates cost estimation should keep them aligned in one place; the constants test (`test_estimate_session_cost_constants_match_advisor`) is the canary.
  - US-048 (biggest (model, task) line) needs per-session model_hint and task_id. Those are NOT on CostLedgerInputSession yet -- US-048 will need a richer input dataclass (or a separate function) that carries the model + task identity per session. Suggest: keep `compute_cost_ledger` minimal for the top-line numbers, add a sibling `compute_top_line` (or similar) that takes a richer input.
  - US-049 (tier-fit savings) needs `user_turn_count` and `avg_prompt_chars` per session plus the cheaper-tier card lookup. The helper `_find_fast_tier_card_in_family` already exists in `models_advisor/advisor.py` -- consider extracting it to `praxis/models_advisor/cards.py` if multiple modules will need it.
  - US-050 (dollar_impact_estimate per moment) modifies the Moment dataclass / persistence path; cost_ledger.py is upstream of moments rendering, so the two stories don't share much code. Use the same chars-per-token + output-multiplier constants for consistency.
  - US-051 (renderer disclaimer) is a reports-layer change. The cost ledger module already enforces the "rough estimate" framing via the dataclass field naming and docstrings; the actual disclaimer text lives in the renderer that consumes CostLedger.

## Iteration 2 - US-048: Biggest (model, task) line
- What I did: Added a sibling aggregator `compute_biggest_line` to praxis/scoring/cost_ledger.py, plus a richer per-session input `BiggestLineInputSession` (started_at, cost_usd, model_hint, task_label) and an output `BiggestLine` (model_hint, task_label, spend_usd, session_count). Groups by (model_hint, task_label) within the current ISO week only and picks the max-spend bucket with a deterministic tiebreak. Added 15 tests in tests/test_cost_ledger.py.
- Files changed: praxis/scoring/cost_ledger.py, tests/test_cost_ledger.py, scripts/ralph/feature/cost-ledger/prd.json
- Verification:
  - python -m pytest tests/test_cost_ledger.py -v -> 34 passed (19 from US-047 + 15 new)
  - python -m pytest -q -> all 728 passed
  - pyright praxis/scoring/cost_ledger.py tests/test_cost_ledger.py -> 0 errors
  - mypy praxis/scoring/cost_ledger.py tests/test_cost_ledger.py -> 0 errors in the two source files (the 23 errors mypy reports are all in pre-existing files: trajectory.py, judge.py, aggregate.py, advisor.py -- same set documented in Iteration 1's handoff)
- What the next iteration should know:
  - Two new dataclasses (BiggestLineInputSession, BiggestLine) live alongside CostLedger* in cost_ledger.py. I chose to keep `compute_cost_ledger` minimal (top-line totals + baseline) and add `compute_biggest_line` as a sibling rather than fold the panel data into CostLedger -- the inputs are richer (need model + task identity) and the panel is conceptually a different aggregation. The caller will compute both from the same week of sessions.
  - Skipping rule: a session is excluded from the biggest-line aggregation iff `cost_usd is None OR model_hint is None OR task_label is None`. The `model_hint`/`task_label`/`cost_usd`-all-required rule is stricter than the parent ledger (which only requires priced cost_usd) because the panel exists to NAME a specific pair -- an 'unknown/unknown' row would be a regression in clarity. If a future story (e.g. US-049 tier-fit) wants to count unidentified-task sessions, it needs a different input.
  - Tiebreak rule (locked in by tests): max spend -> max session_count -> ascending (model_hint, task_label). The session-count tier exists because two equal-spend pairs read as "the busier one matters more" to a user; the alphabetical tier is purely for determinism. Float ties at exact USD are unlikely in practice but the test suite locks them in so renderers stay stable across runs.
  - Window: current ISO week ONLY (Monday-inclusive). Baseline-window sessions are silently skipped here -- the baseline answer is exposed via `CostLedger.baseline_weekly_mean_usd`, so duplicating it would be confusing.
  - Empty-result convention: `BiggestLine(model_hint=None, task_label=None, spend_usd=0.0, session_count=0)`. Renderers should treat `model_hint is None` as the signal to omit the panel row entirely, NOT to print "no biggest line" prose.
  - US-049 (tier-fit savings): needs `user_turn_count` and `avg_prompt_chars` per session AND the cheaper-tier card lookup. The existing `find_card_for_model_hint` returns one card; the helper `_find_fast_tier_card_in_family` in models_advisor/advisor.py is the cheaper-tier resolver -- still private, still worth extracting to praxis/models_advisor/cards.py if US-049 is the second caller. The output should expose the qualifying-session count AND the savings estimate to the renderer (same renderer-facing shape as BiggestLine, distinct dataclass).
  - US-050 (per-moment dollar_impact_estimate): downstream of moments persistence; the chars-per-token + output-multiplier constants `COST_CHARS_PER_TOKEN` and `COST_OUTPUT_TO_INPUT_RATIO` should be reused so the per-moment estimates and the weekly ledger agree.
  - US-051 (renderer disclaimer): purely a reports-layer change. cost_ledger.py is intentionally framing-agnostic; the disclaimer literal lives in the renderer.

- What the next iteration should know:
  - The "inlined fallback" pattern is: name `'Libre Baskerville'` first in display font-family declarations and `Georgia` second. If the user has Libre Baskerville installed locally, the digest renders identically to the v0.1 scan report. If not, the browser falls back to Georgia (which ships on every default desktop OS). Self-containment is preserved because we never fetch the font - we just name it.
  - Do NOT add a `<link rel="stylesheet" href="https://fonts.googleapis.com/...">` for Libre Baskerville. That would break US-061's self-containment and is now also guarded by test_render_does_not_fetch_libre_baskerville (which checks for fonts.googleapis.com, fonts.gstatic.com, and @font-face by string).
  - The chrome/sans stack is `-apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif` (unchanged from iteration 2). It is used for eyebrow labels, placeholder text, masthead-meta, moment-label, ledger-label, dim-aside, traj-band, follow-up-outcome.
  - Color tokens that are declared but not yet used by digest_html.py: --primary-hover, --primary-soft, --primary-line, --cream-300, --cream-400, --ink-700, --ink-300, --ink-100, --border-medium. These are wired in for visual continuity with v0.1 so US-064/US-065 (or any future polish pass) can reach for them without growing the palette ad-hoc.
  - US-064 is next: write to ~/.praxis/weeks/<iso>.html and update ~/.praxis/latest.html symlink. The renderer is a pure str-returning function; persistence is intentionally a separate concern. Look at praxis/storage/ and existing ~/.praxis/ path patterns (see praxis.config or praxis.storage.weekly if it exists) before inventing a new convention. Use pathlib.Path, handle the case where the symlink target already exists, and write the file atomically (write to a temp file in the same dir, then os.replace).
  - US-065 is the final story: ensure no `<synthetic>` strings or unredacted provider API keys leak into the rendered HTML. The renderer is pure, so this is enforced at the boundary between domain models and WeeklyDigest construction; current dataclasses do html.escape on their string fields, which protects against HTML injection but not against secret leakage. The secret-redaction patterns live in praxis.security or praxis.privacy (grep for "redact" / "sk-ant-" / "synthetic" to find them).

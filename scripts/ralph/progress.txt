## Iteration 4 - US-064: Write to weeks directory and update latest.html symlink
- What I did: Added persistence to the digest renderer. New public function `write_digest(digest, home=None) -> Path` in praxis/reports/digest_html.py renders the digest and writes `<home>/weeks/<iso>.html` atomically (temp file + os.replace) then refreshes `<home>/latest.html` via a private `_update_latest_pointer` helper. The pointer is a relative symlink on POSIX (so it survives ~/.praxis being moved or backed up) and falls back to `shutil.copy2(target, latest)` on platforms where `Path.symlink_to` raises OSError or NotImplementedError (Windows without developer mode, certain FAT filesystems). Home directory resolution reuses `praxis.storage.profile_store.resolve_home`, so the PRAXIS_HOME env override the rest of the storage layer respects works here too. Added 13 tests under "US-064: write to disk + latest pointer" covering: path layout, weeks-dir auto-create, return value, content-matches-render, latest pointer existence, latest dereferences to the same bytes, relative symlink target, overwrite same week (path stable, bytes change), latest follows newest week, replaces a pre-existing regular file at latest.html, replaces a broken symlink, no leftover .tmp after a successful write, and honors PRAXIS_HOME env when `home=` is omitted.
- Files changed: praxis/reports/digest_html.py (write_digest + _update_latest_pointer + imports), tests/test_digest_html.py (13 new tests + Path/os imports), scripts/ralph/feature/html-digest-renderer/prd.json (US-064 passes=true).
- Verification:
  - `uv run --extra dev pytest` -> 745 passed in 0.55s (was 732 + 13 new).

  - Smoke test: rendered three digests (2026-W21, 2026-W21 again with a later generated_at, then 2026-W22) under a tempdir; confirmed weeks/2026-W21.html overwrote in place on the second call, latest.html stayed a relative symlink the whole time, and the third call retargeted latest.html at weeks/2026-W22.html.
- What the next iteration should know:
  - Persistence and rendering are now both in praxis/reports/digest_html.py. The pure `render(digest) -> str` is still public for tests/pipelines that want to inspect HTML without I/O; `write_digest(digest, home=None) -> Path` is the production-side entry point. There is no separate persistence module - colocating with the renderer kept the contract simple and avoided a circular-import hazard with praxis.storage.profile_store (which `resolve_home` is imported from).
  - The atomic-write convention is: write to `<target>.tmp` then `os.replace(tmp, target)`. On POSIX `os.replace` is atomic across the same filesystem; the weeks/ dir is always on the same fs as the temp file because we put both inside `<home>/weeks/`. If a future iteration moves the write into a different directory, double-check the same-fs property.
  - `_update_latest_pointer` is the only place that touches `latest.html`. If a future story (US-065 etc.) needs to read or invalidate the pointer, route it through this helper - the symlink-or-copy fallback logic should not be duplicated.
  - The symlink target is RELATIVE (`weeks/<iso>.html`). On the Windows-copy fallback, `latest.html` is a regular file - readers should not assume `latest.is_symlink()`. `latest.read_text()` is the portable way to consume it.
  - The `test_write_digest_uses_relative_symlink_target` and `test_write_digest_replaces_broken_symlink` tests pytest.skip on platforms where symlink creation fails. The remaining tests assert behavior via content/exists checks so they pass on both code paths.
  - The CLI does not yet call `write_digest`. praxis/cli/__main__.py still writes the v0.1 `report.html` to `<home>/report.html`. Wiring `praxis week` (spec section 12.1) to call `write_digest` is out of scope for this factory; this is the renderer + persistence layer only.
  - For US-065 (no raw secrets / synthetic markers / PII): now that write_digest is on disk, a useful test pattern is to construct a WeeklyDigest with strings that contain `<synthetic>` markers or fake API keys (e.g. `sk-ant-api03-AAA...`), call write_digest, and assert the on-disk bytes do not contain those substrings. The renderer currently html.escapes inputs but does not apply redact_secrets, so US-065 likely needs to either (a) wire redact_secrets through the panel dataclasses before render, or (b) add a final-pass sweep that strips `<synthetic>` markers and asserts no provider key patterns survived.

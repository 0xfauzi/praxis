  - uv run mypy praxis  -> still 34 pre-existing errors in 6 files, zero new.
- What the next iteration should know:
  - Module-level pattern list is now `_PATTERNS: tuple[tuple[re.Pattern[str], str], ...]` (not `_PROVIDER_PATTERNS`). If US-011 wants to add another rule, append `(compiled_pattern, replacement_string)` to this tuple; the replacement may contain backrefs.
  - Idempotence (US-011) is already de facto preserved: provider regexes have no `[` in their char classes, and the new _GENERIC_LABELED_SECRET value class also excludes `[` (and the {20,} length defeats the 8-char `REDACTED` body), so a second pass over `[REDACTED]` cannot match. Verified by test_generic_does_not_re_redact_placeholder.   - The labeled-secret regex uses `\W*` (zero-or-more non-word chars) as the separator. This deliberately includes `\n`, so multi-line `key:\n  abc...` patterns are still redacted; but intervening English words (e.g., "password is wrong") break the match because the next `\w` stops `\W*` and the value class doesn't admit a leading letter-word. Keep this property when extending.
  - The literal alternation is exactly `key|token|secret|password` -- singular, no plurals, no compound forms like `API_KEY` (since `\bKEY\b` does not match inside `API_KEY`). If a future story wants to cover compound env-var names, that is a new requirement; do not silently widen this regex.

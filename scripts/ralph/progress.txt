    * Median (not mean) on purpose - one freakishly long debugging session in the recurring group should not inflate the suggested-skill payoff to "30 min/week saved" when most of the recurrences were 5-minute checks.
    * Defensive 0.0 fallback when a group has zero session durations (currently unreachable because every cluster in an eligible group has >= MIN_TOKENS_FOR_COMPARISON content tokens but is not forced to have >= 1 session). `statistics.median([])` raises `StatisticsError`, so the fallback prevents a future relaxation of cluster eligibility from crashing the detector.
    * Test helper split into `_cluster` (defaults duration_minutes per session) and `_cluster_with_durations` (takes explicit (sid, minutes) pairs). Reach for the second when the test body needs to assert on the median; reach for the first when it only cares about the matching/grouping shape.
  - Hooks for callers integrating this into the report layer:
    * The orchestrator/clustering pipeline (praxis/scoring/clustering.py / praxis/orchestrator.py) builds `Task` objects today and would need an adapter that turns each Task + its underlying sessions into a `Cluster` -- first_sentence pulled from the earliest session's first user turn, session_durations_minutes derived from each session's `started_at`/`ended_at` (or equivalent elapsed field on `Session`). Where the report layer actually wires the call: search for `# US-015` once integration starts.
    * The "a skill could reclaim ~X min/week" hint = `repeat_task.estimated_minutes_per_occurrence * repeat_task.occurrences`. Don't compute it inside `detect_repeats` -- the multiplication belongs to the renderer so the model layer stays presentation-free.

    * `Cluster` is frozen, so `__post_init__` can only validate, not coerce. If a caller wants to pass `list[int]` durations, they need to convert to `list[float]` themselves.

## Iteration 2 - US-028: Low-confidence sessions escalate to pass 2
- What I did: Added `score_session_pass2` in judge.py (a thin wrapper over the existing `score_session` that uses the frontier models, one session per call, with no pass-1 context) and `score_one_session_pass2` in aggregate.py. Wired the orchestrator to inspect each pass-1 JudgeResult's `confidence` field and, when it equals `"low"`, re-run the session through pass 2 and replace the pass-1 SessionScore with the pass-2 one before persistence. Pass-2 failure (None return) falls back to keeping the pass-1 score so sessions are never silently dropped.
- Files changed: praxis/scoring/judge.py, praxis/scoring/aggregate.py, praxis/orchestrator.py, tests/test_judge.py, tests/test_orchestrator.py
- Verification: `uv run pytest -q` (711 passed, up from 702 baseline; +9 new tests for pass-2). `uv run mypy praxis` (34 errors, same as pre-change baseline; no new errors introduced).
- What the next iteration should know:
  - The pass-2 entrypoint is `praxis.scoring.judge.score_session_pass2`; the wrapper that returns a SessionScore is `praxis.scoring.aggregate.score_one_session_pass2`. Tests can monkeypatch either - the orchestrator tests patch `praxis.scoring.aggregate.score_session_pass2` so the wrapper still builds a real SessionScore around the fake JudgeResult.
  - The pass-1 -> pass-2 handoff intentionally passes ONLY the Session object to pass 2 (no JudgeResult, scores, rationale, or moments). This is enforced by both a unit test (test_pass2_receives_only_the_session_no_pass1_context in test_judge.py) and an integration test (test_pass2_call_does_not_include_pass1_outputs in test_orchestrator.py). Don't add a "pass-1 context" parameter without revisiting those tests and the spec §9.1 contract.
  - US-029 needs to persist BOTH pass-1 and pass-2 rows with a `judge_pass` column. The current orchestrator replaces the pass-1 SessionScore in memory before calling `store.save_session_score`, so only the pass-2 row reaches the DB today. The simplest US-029 path: persist pass-1 first (with judge_pass=1), then if escalation happens persist pass-2 too (with judge_pass=2). The `save_session_score` currently uses `INSERT OR REPLACE` keyed on stable_id; that primary key will need to change (composite (stable_id, judge_pass) or a synthetic id).
  - In the orchestrator loop, `score.judge_result.confidence == "low"` is the escalation gate. `JudgeResult.confidence` defaults to "medium" when the cheap model omits or returns a malformed value, so a missing self-rating does NOT trigger pass 2 - intentional per spec §9.3 and US-019.
  - For tests that build a JudgeResult fixture with a custom confidence, the field name is `confidence` (literal "low"|"medium"|"high"). Mypy needs `# type: ignore[arg-type]` when passing a str variable (the field is a Literal); the new `_pass1_result` helper in test_orchestrator.py shows the pattern.
  - mypy baseline unchanged at 34 errors across `behavior/trajectory.py`, `cli/__main__.py`, `models_advisor/advisor.py`, `scoring/aggregate.py`, `scoring/coach.py`, `scoring/judge.py`.

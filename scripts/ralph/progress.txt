## Iteration 2 - US-075: Auxiliary commands present
- What I did: Wired the v0.2 auxiliary verbs onto the CLI surface. `praxis re-score <stable_id>` looks up the row, re-parses the source file via the matching scanner, runs the frontier judge, and overwrites session_scores + moments. `praxis baseline` / `praxis history` / `praxis show <iso>` are strictly read-only views over persisted rows. `praxis scan` no longer renders a digest -- it now prints a one-line scan summary and tells the user to run `praxis week` for the digest.
- Files changed:
  - praxis/orchestrator.py: added `re_score_session()`, `ReScoreError` (with codes `not_found`/`unreadable`/`no_judge`), `_scanner_for_provider()`, and `list_persisted_weeks()`. Imported `Path` and `Any`.
  - praxis/storage/profile_store.py: added `load_one_session_score(stable_id)` returning a row dict (same shape as `load_session_scores` items).
  - praxis/cli/__main__.py: added `cmd_re_score`, `cmd_baseline`, `cmd_history`, `cmd_show`; rewrote `cmd_scan` to emit a one-line summary and dropped scan's `--open` flag (no HTML written anymore). Registered all four new subparsers. Module docstring updated to enumerate the v0.2 surface.
  - tests/test_cli.py: 14 new tests covering subparser registration, re-score happy path + not-found + no-judge exit codes, baseline (forming + populated), history (empty + sorted), show (renders + malformed-iso rejection), scan-does-not-render, and preserved-from-v0.1 commands (status / rubric / models).
- Verification: `python -m pytest` -> 716 passed (was 702; +14 new tests). `mypy praxis` -> still 34 errors, all pre-existing (none introduced by this iteration). Manual smoke-tested `baseline`, `history`, and `scan` against /tmp/praxis-cli-smoke.
- What the next iteration should know:
  - **US-076 (no-API-key exit 2)**: `cmd_re_score` already returns exit 2 for `ReScoreError(code="no_judge")`. The same wiring needs to land in `cmd_week` / `cmd_scan`: detect the absence of both `ANTHROPIC_API_KEY` and `OPENAI_API_KEY` at the top of the command and exit 2 with a message naming both env vars. That detection lives in `praxis.scoring.judge.score_session` today (returns None), so the cleanest place is a tiny helper in praxis/config.py or orchestrator.py the CLI calls before invoking the pipeline.
  - **US-077 (no sessions exit 3)**: `cmd_week` / `cmd_show` currently render an empty digest and exit 0 even when zero sessions land in the window. Switch to exit 3 (matching the existing `cmd_follow_up` precedent) when `summary.snapshot.session_count == 0` for the targeted week. Keep `praxis week` on the *current* week happy-pathing through 0 sessions only when the scan also returned 0 (don't fail brand-new users on day 1 if they have actual sessions but none scored yet -- check session_count, not whether the snapshot is empty).
  - **US-078 (removed commands)**: `cmd_install_daemon` and its subparser are still wired -- leave them in place for now; US-078 removes them. The `--no-judge` flag does not currently exist anywhere in the CLI, so US-078 may already be partially satisfied; verify with a grep before claiming.
  - `praxis show <iso>` reuses `run_weekly(week_iso=...)` so it benefits from the same past-week filter and ISO-week parser. Don't duplicate that logic in `cmd_show`.
  - The baseline command intentionally renders rates as omitted (not "0.00") because the rates aren't stored in session_scores -- they'd require re-parsing source files, which breaks read-only. If a future story persists rates per session, drop the zeros and surface them.
  - `list_persisted_weeks()` derives history from session_scores rather than the (still-empty) `weekly_digests` table, so it works before the digest-persistence story lands. When that story does land, prefer `weekly_digests` rows for richer per-week metadata (trajectory label, headline moment, cost).

## Iteration 4 - US-077: Exit code 3 when no sessions in the window
- What I did: Added `no_sessions_message(week_iso)` helper in praxis/orchestrator.py and wired it into `cmd_week` / `cmd_show` so that any digest-rendering command exits 3 with a clear message naming the targeted ISO week when the snapshot has zero sessions. The gate runs AFTER the US-076 exit-2 gate so "no key" still trumps "no sessions" (more actionable message). `cmd_scan` deliberately keeps its exit-0-on-empty behavior so the cron worker does not surface a spurious failure on an idle day.
- Files changed:
  - praxis/orchestrator.py: added `no_sessions_message()` helper. No new module-level constant -- the message is composed from the ISO-week label so tests can assert the week tag is in the output.
  - praxis/cli/__main__.py: imported `no_sessions_message`, added the `summary.snapshot.session_count == 0` gate in `cmd_week` (after the InvalidWeekError handler, before render/HTML/notify) and in `cmd_show` (after the InvalidWeekError handler, before render). Documented exit code 3 in both docstrings.
  - tests/test_cli.py:
    - Updated existing tests that relied on the old "empty data exits 0" behavior:
      - `test_week_with_no_data_exits_zero` renamed to `test_week_with_data_renders_and_exits_zero`; now seeds one current-week session before asserting exit 0.
      - `test_week_dry_run_does_not_create_html` now seeds a current-week session so the run reaches the HTML decision point.
      - `test_week_explain_judging_prints_explainer` and `test_week_explain_judging_notes_frontier_only` now seed a current-week session so the explainer block prints (otherwise exit 3 short-circuits before render).
      - `test_week_with_only_anthropic_key_proceeds` / `_openai_key_proceeds` / `_iso_bypasses_api_key_check` / `_dry_run_bypasses_api_key_check` now assert `code != 2` rather than `== 0` -- the original intent was "the key gate did not fire", which is what `!= 2` asserts; exit 3 with no seeded data is the correct US-077 behavior.
    - Added 7 new US-077 tests at the bottom of the file: `test_week_current_window_with_no_sessions_exits_3`, `test_week_past_week_with_no_sessions_exits_3`, `test_week_dry_run_with_no_sessions_exits_3`, `test_show_with_no_sessions_exits_3`, `test_no_api_key_trumps_no_sessions` (precedence), `test_week_with_seeded_session_does_not_exit_3` (positive case), `test_scan_with_no_sessions_does_not_exit_3` (scan exemption).
  - scripts/ralph/feature/cli-surface/prd.json: flipped US-077 to passes=true with implementation notes.
- Verification: `python -m pytest` -> 731 passed (was 724; +7 new tests, 0 broken). `mypy praxis` -> still 34 errors, all pre-existing (no new errors introduced). Manual smoke against /tmp/praxis-us077-smoke: `praxis week` (no key) exits 2; `praxis week` (key set, no sessions) exits 3 with `No sessions found in <iso>` message; `praxis week --week 2026-W21`, `praxis week --dry-run`, and `praxis show 2026-W21` all exit 3 with the targeted ISO week in the message; `praxis baseline` (no key, no data) still exits 0.
- What the next iteration should know:
  - **US-078 (removed commands)**: `--no-judge` is already absent from the CLI (still grep-able to confirm). `cmd_install_daemon` and its `install-daemon` subparser are still present in praxis/cli/__main__.py; US-078 removes them. Spec section 11 also says "praxis install-daemon (the daily one) | Removed. Replaced by praxis install-weekly (Section 12.4)." -- US-078 only mandates removal; the `install-weekly` replacement is a separate later story per the PRD's scope.
  - **Why `cmd_scan` is exempt from exit 3**: the spec wording "scan returns zero in-window sessions" reads ambiguously, but spec section 12.1 explicitly frames `praxis scan` as the cron-driven data-mover ("power-user: just scan and score, no digest. Used by the cron job."). If scan exited 3 on idle days, every launchd / systemd timer / Task Scheduler run with no new sessions would surface a job failure. `test_scan_with_no_sessions_does_not_exit_3` locks this in; do not remove that test in US-078 even though scan is being kept.
  - **Gate ordering invariant**: in `cmd_week`, the order is (1) malformed --week -> exit 1, (2) no API key on judge-needing path -> exit 2, (3) zero sessions -> exit 3, (4) digest render -> exit 0. `test_no_api_key_trumps_no_sessions` locks in the (2) > (3) precedence; if a future story changes the ordering, that test will break, which is the intended signal.
  - **Message stability**: `no_sessions_message()` is the single source of truth for the exit-3 wording. The test assertions check `"No sessions found"` and (where applicable) the ISO-week tag, so wording tweaks beyond those two anchors won't break tests. The ISO-week tag in the message is the documented contract -- callers should not remove it.
  - **Test seeding pattern**: tests that need a populated current-week digest call `_seed_score("sess-name", datetime.now(timezone.utc))`. Use `datetime.now(timezone.utc)` (not `_utcnow()` or a fixed date) so the row always falls inside the rolling 7-day window of the current-week branch. For past-week tests, use a fixed date inside the targeted ISO week (e.g. `datetime(2026, 5, 20, ...)` for 2026-W21).

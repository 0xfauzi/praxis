## Iteration 1 - US-079: install-weekly creates and loads the plist
- What I did: Added `praxis install-weekly` subcommand backed by `praxis/cli/install_weekly.py`. Generates ~/Library/LaunchAgents/co.praxis.weekly.plist (Label=co.praxis.weekly) using `schedule.day/hour/minute` from ~/.praxis/config.toml and loads it with `launchctl load -w`. Idempotent re-runs unload first. CLI exits 4 with stderr message on launchctl failure (InstallWeeklyError surfacing returncode + stderr).
- Files changed: praxis/cli/install_weekly.py (new), praxis/cli/__main__.py (cmd_install_weekly + subparser), tests/test_install_weekly.py (new, 12 tests), scripts/ralph/feature/macos-launch-agent/prd.json (passes=true), scripts/ralph/progress.txt (this entry).
- Verification: `uv run pytest -q` -> 1024 passed (12 new + 1012 existing). `uv run pyright praxis/cli/install_weekly.py` -> 0 errors. The 3 pre-existing pyright errors on cli/__main__.py (WeeklyRunSummary vs RunSummary) are unchanged before/after this commit; confirmed by git stash + pyright comparison.
- What the next iteration should know:
  - Patterns established:
    * Subprocess is monkeypatched via `praxis.cli.install_weekly.subprocess.run`; tests do not call real launchctl. Reuse this stub fixture (`fake_launchctl`) when implementing US-080 uninstall-weekly.
    * The plist path resolver `plist_path(home=...)` accepts a home override but defaults to `Path.home()`, which the tmp_home conftest fixture patches; that's how tests land the plist inside tmp_path.
    * `PLIST_LABEL = "co.praxis.weekly"` is exported from install_weekly.py; uninstall-weekly should import and reuse it (don't duplicate the string).
    * `_WEEKDAY_BY_NAME` maps 'sunday'..'saturday' to 0..6 per Apple's launchd Weekday spec.
  - Hooks for upcoming stories:
    * US-080 (uninstall-weekly): needs to `launchctl unload <plist>` then delete the file; if file missing or unload fails, must still exit 0 per AC. Reuse `plist_path()` and `PLIST_LABEL`.
    * US-081 / US-082 (--notify path inside `praxis week`): the existing `_post_notify` in cli/__main__.py already shells out to osascript and includes the trajectory label in the title. ACs may want osascript moved to a dedicated module so test stubbing is easier, and the BODY (not just title) should mention `~/.praxis/latest.html`. Today the body only references `~/.praxis/weeks/{iso}.html` -- check whether US-081's AC ("opening ~/.praxis/latest.html") wants the body changed.
    * US-083 (non-macOS path): cmd_install_weekly currently prints a placeholder stderr message on non-Darwin and returns 0. That placeholder is the seam to flesh out: print the systemd timer / Task Scheduler XML to stdout AND save to ~/.praxis/install-weekly-snippet.txt.
  - Gotchas:
    * The pre-existing pyright errors in cli/__main__.py (WeeklyRunSummary type mismatch at lines 145/150/332) are noise from an orchestrator/reports type-coupling issue unrelated to this story. Don't try to "fix" them as part of macos-launch-agent stories unless explicitly assigned.
    * `_resolve_praxis_command()` falls back to `[sys.executable, '-m', 'praxis.cli']` when `shutil.which('praxis')` returns None; this matters when running install-weekly outside an activated venv. Tests don't exercise the fallback path, but they should not need to.

## Iteration 2 - US-080: uninstall-weekly removes the plist
- What I did: Added `praxis uninstall-weekly` subcommand backed by `uninstall_weekly_macos()` in praxis/cli/install_weekly.py. It runs `launchctl unload` on the existing plist (best-effort) then deletes the file, returning True. When the plist does not exist, it returns False without shelling out, and the CLI exits 0 in both cases. Non-Darwin platforms exit 0 with an explanatory stderr message.
- Files changed: praxis/cli/install_weekly.py (added uninstall_weekly_macos + docstring update), praxis/cli/__main__.py (cmd_uninstall_weekly + 'uninstall-weekly' subparser), tests/test_install_weekly.py (added 6 tests, import uninstall_weekly_macos, header updated), scripts/ralph/feature/macos-launch-agent/prd.json (passes=true), scripts/ralph/progress.txt (this entry).
- Verification: `uv run pytest -q` -> 1030 passed (6 new + 1024 existing). `uv run pyright praxis/cli/install_weekly.py` -> 0 errors. `uv run pyright praxis/cli/__main__.py` -> 3 errors, identical to baseline before this commit (verified via `git stash` round-trip); they are the pre-existing WeeklyRunSummary issue documented in iteration 1.
- What the next iteration should know:
  - Patterns established:
    * `uninstall_weekly_macos(home=None)` returns `bool` indicating whether anything was actually removed. The CLI uses this to choose between "Removed..." vs "No weekly LaunchAgent found at..." messaging.
    * The "tolerate launchctl unload failure" rule -- launchctl returns non-zero when the job is not currently loaded, and we cannot distinguish that from a real error. uninstall always proceeds to delete the file. If a future story needs to surface real unload errors, it must add a separate code path that distinguishes them (e.g., parse stderr for the "Could not find specified service" text), not change this default.
  - Hooks for upcoming stories:
    * US-081 (--notify body / osascript): `_post_notify` in cli/__main__.py currently puts the trajectory label in the title only and uses a `~/.praxis/weeks/{iso}.html` body. AC US-081 wants the body to mention `~/.praxis/latest.html` -- check whether to change the body text or introduce a `latest.html` symlink/copy. Existing notify happy-path tests (if any) live in tests/ for the week command; grep for `_post_notify` before touching.
    * US-082 (trajectory in body + non-crashing osascript): `_post_notify` already wraps the osascript call in a broad try/except, but the AC says "if osascript fails for any reason, the run logs the failure and still exits 0" -- need a test that covers a FileNotFoundError (osascript binary missing) explicitly, since today's try/except is best-effort but unverified by tests.
    * US-083 (non-macOS install-weekly path): the placeholder "not yet implemented" stderr message in cmd_install_weekly is the seam to flesh out -- print the systemd / Task Scheduler XML to stdout AND save to ~/.praxis/install-weekly-snippet.txt. The matching non-macOS branch for cmd_uninstall_weekly is already a sensible no-op ("non-macOS has no scheduled job to remove."); US-083 may not need to touch it.
  - Gotchas:
    * `fake_launchctl` fixture is reusable but accumulates calls across `install_weekly_macos()` + `uninstall_weekly_macos()` in the same test, so slice the list from the install call count before asserting on uninstall's behavior (see test_uninstall_weekly_unloads_and_deletes_plist).
    * `cmd_uninstall_weekly` imports from `praxis.cli.install_weekly` inside the function (not at module top) to match the existing install pattern -- keeps non-macOS imports off the hot path.
